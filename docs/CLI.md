# CLI 开发规范

Biny 的 CLI 为用户、脚本和 Agent 提供可直接调用的模块能力。新增或扩展 memory 这类具有独立业务职责的模块时，应提供完成实际任务所需的 CLI 入口，并复用模块已有的执行链路。

实际命令、执行条件与操作示例由 [CLI 使用指南](CLI_USAGE.md)维护；完整阅读入口见[文档索引](README.md)。

## 后续新增命令

先查看现有模块的 `--help` 和所属功能专题，确认用户任务是否已由现有命令或参数覆盖。确有缺口时，找到所属服务与现有校验，补一条命令适配，并在同一次修改中验证实际结果、更新帮助与使用指南。不要只看到其他入口有某个内部方法就机械新增命令。

核对覆盖范围时同时检查命令注册、实际分发和所属服务，不能只凭顶层帮助判断是否齐全。区分已有入口能完成的任务、已有业务能力缺少的入口，以及尚未实现的产品能力；交付按这三类说明，不用命令数量代替覆盖结论。涉及读取与汇总时说明分支、分页、配置作用范围和去重依据。

配置、会话和 Desktop 状态各自沿用所属存储与进程。需要 Desktop 凭据、PTY 或预览的操作连接现有 Desktop；查询运行会话时使用明确的会话 ID。不要为 CLI 另造状态副本，或在连接失败后自动切换实现。

## 命令范围

- 按业务模块组织命令，采用 `biny <模块> <操作>`。已有命令组优先扩展，同一操作保留一个清晰入口，不新增同义命令、重复别名或另一套顶层入口。
- 只暴露有实际使用场景的操作，不按内部方法逐个映射命令，也不为凑齐 CRUD 增加能力。内部辅助模块无需单独提供 CLI。
- 参数只覆盖本次任务需要的输入和范围；沿用所属模块的默认值，不把内部实现细节全部做成开关，不为假设中的未来需求预留参数。
- CLI 与模型工具按调用场景选择入口。新增 CLI 不自动要求再注册一个同名模型工具，也不自动删除已有工具；执行逻辑复用同一所属服务。

例如，memory 已有 `biny memory list`、`biny memory search`、`biny memory add` 等入口。增加一种检索条件时，先扩展 `memory search` 的必要参数；只有用户任务和执行语义不同，才新增操作。具体能力、参数和限制由[长期记忆](MEMORY.md)维护，本规范不重复列命令清单。

## 实现边界

`src/cli/index.ts` 使用 Commander 注册命令，`src/cli/commands/` 将参数转换为所属模块的调用，并格式化结果。注册函数可以按命令域放在对应文件中；不为简单命令增加通用分发层、基类或插件框架。

领域规则、查询、持久化和状态转换留在所属服务。由 Runtime Host 管理的能力继续通过 Host 执行，CLI 不复制这些能力的存储、缓存或后台任务机制，不绕过现有的权限、会话归属和写入所有权规则。当前 memory 的适配入口见 [localCapabilities.ts](../src/cli/commands/localCapabilities.ts)。

输入格式在 CLI 适配边界解析，领域约束由所属服务校验；复用已有 schema 和错误处理，不在多层重复维护同一规则。所有修改遵守[实现范围与必要性](DEVELOPMENT.md#实现范围与必要性)，不得借新增 CLI 自行添加防护性代码。

## 输入与输出

- 帮助说明操作、必要参数、默认范围及实际副作用；参数名与同类现有命令保持一致。
- 工作区以启动目录为准。跨会话、账号或全局数据操作明确采用所属模块的目标规则，不根据“最近使用”自行猜测对象。
- 面向脚本或 Agent 的一次性操作提供 `--json`，stdout 输出单一可解析结果，不混入日志或进度文本。持续流式命令按其明确声明的输出协议执行，不套用单结果格式。
- 执行错误写入 stderr 并返回非零退出码；沿用已有命令的业务状态语义。合法空结果与读取失败分开，不把异常转换成空列表或成功结果。
- 确认、取消与资源释放复用所属能力的现有契约，不自行增加确认步骤或改变操作范围。

## 验证与文档

验证真实命令入口的参数传递、领域调用结果和输出；涉及写入时检查实际状态变化，涉及错误时检查 stderr 与退出码。优先扩展已有测试，不为纯转发另造测试框架；测试隔离、回归要求和验证命令见[贡献指南](../CONTRIBUTING.md#行为变更)。

命令的用法与限制更新到所属功能专题，帮助与文档保持一致。纯规范修改运行 `pnpm check:docs`；实际 CLI 行为变更再执行相关入口测试，不能只凭命令已注册或帮助可显示判定功能可用。
