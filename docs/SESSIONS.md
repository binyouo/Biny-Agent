# 会话与恢复

会话保存对话、工具调用和运行结果。Desktop、TUI 与 CLI chat 使用共享的本机 Runtime Host；一次性 `run` 也经 Host 执行，输出一个任务结果。

## 一次对话如何留下记录

客户端提交输入后，Runtime Host 对目标会话进行准入并取得执行所有权，AgentSession 组装上下文、请求模型和执行工具。用户消息、助手消息、工具调用、工具结果及错误进入 Session JSONL；客户端根据运行事件展示增量内容。

| 数据 | 实际职责 |
| --- | --- |
| Session JSONL | 原始对话和工具事件，是恢复历史的事实来源。 |
| 消息身份与父关系 | 确定对话链和分支点，不能由工具名称或展示顺序猜测。 |
| Catalog | 管理标题、置顶、归档和分支列表；归档不等于删除事件。 |
| 搜索与界面投影 | 为查询和展示整理历史，可重建；投影缺失不证明原始会话消失。 |
| 断点、租约与运行记录 | 保存执行阶段、写入所有权和已有结果，用于恢复判断。 |

同一会话的写入受租约约束，多客户端连接不会各自成为独立写入者。恢复读取事件与执行状态，重建下一回合需要的上下文；它还需核对工具是否已经派发、结果是否可信。历史内容、回合终态和任务验收分别保存，不能由回答文字推断整段执行已经完成。

模型读取历史时会收到用户消息原始的发送时间与已记录的发送时区，用于解释当时说的“今天”“明天”等相对日期；发送时间不代表事件发生、到期或工作完成时间。旧消息缺少时区或时区为空时明确标记未知，不按当前机器时区补造。时间说明只进入模型上下文，聊天正文与原始记录保持原样。

每次开始生成时提供当前本地时间；从断点恢复、重新生成或暂停后空输入继续时重新采样，历史消息的发送时间保持原样。当前日期、星期和 UTC 偏移另有独立预算，不随 Activity、日报等辅助上下文一起省略。同一次生成的工具循环沿用开始时的时间快照。

## 选择入口

命令行的 `session rename/pin/unpin/archive/unarchive/duplicate/delete` 通过 Desktop 管理同一份会话元数据与记录；`session create/usage/compact` 连接已有 Host。`session messages/search` 从本地记录读取当前消息分支或查找会话，`usage` 汇总已落盘的全局用量。`tool list/call` 查询目录或经所属 Host 执行工具，沿用权限、审计和空闲会话准入。分页、去重依据与使用条件见 [CLI 使用指南](CLI_USAGE.md#会话用量与工具)。

| 入口 | 用途 |
| --- | --- |
| Desktop | 查看项目和聊天，处理附件、工具审批与交互内容。 |
| `biny`、`biny chat`、`biny tui` | 在当前项目开始终端对话。 |
| `biny run "任务"` | 执行一次性任务。 |
| `biny resume` | 从终端会话选择器恢复历史。 |

CLI 以启动时的当前目录作为工作区。在目标项目中运行命令；同名但路径不同的项目有不同会话分区。

`biny history search "关键词"` 跨项目检索原始对话，结果带来源文件路径，区分不同项目的同名会话。全文缓存保存在 agent 目录的 `search/sessions-v2.sqlite`；首次使用需从 JSONL 建立索引，历史较多时仍需等待。索引写入在工作线程分批执行，可取消；升级不修改原始会话或旧 `sessions.sqlite` 文件。

Desktop 连续选择会话时以最后一次选择为准，无需等待前一次读取或转场动画完成；切换项目保留已展开的文件夹，加载失败保留最后打开的会话。加载期间输入区暂不可操作，防止把消息发给旧会话。跨项目的 Runtime Host 在后台准备，不创建窗口或显示额外 Dock 图标；项目内的会话共用 Host，离开后仍在运行的任务继续执行。

消息菜单的“查看引用来源”只接受当前导航内最近一次查询的结果。已打开的来源弹窗保留原项目归属；关闭后较早查询不会重新打开它，点击来源仍返回来源项目。

会话行悬停或键盘聚焦时显示删除按钮；首次点击变为红色“删除”，再次点击执行。移开鼠标、离开焦点、按 Escape 或等待 3 秒会取消确认；Shift 点击直接删除。右键选择“多选”可跨文件夹勾选会话，顶部显示数量并一次确认批量删除，Escape 退出多选。删除无法撤销，不删除项目文件；运行中会话须先停止任务。确认后立即退出目标聊天，会话行上浮并模糊淡出，750ms 后从列表移除；记录清理在后台完成，全文索引扫描与等锁在工作线程执行，前一次清理未结束时仍可继续删除其他会话。失败项恢复原位置并显示原因，可重新打开或重试；减少动态效果模式立即隐藏目标行。


## 终端对话

在目标项目运行 `biny tui` 或 `biny chat`。输入框的边框颜色随 thinking level 变化，编辑、历史和命令补全使用同一套终端输入机制。输入 `/` 选择命令，Tab 补全；Enter 发送消息或确认命令候选，必填参数命令会留在输入框中等待补齐。

`/skills` 打开可搜索的技能选择器。确认技能或输入 `/skill:` 选择补全候选后，技能名称只填入草稿，已有正文保留；补充任务并再次按 Enter 才发送。Esc 关闭选择器并保留草稿。`/subagent` 菜单提供任务状态、Agent 定义、启动与取消入口，启动和取消先填入待补齐的命令。

工具记录默认显示语义标题、状态、耗时和可用的输出行数或修改统计，连续调用紧凑排列。查询结果和报告使用内联命令卡片，摘要最多八个终端行；状态、任务与失败原因优先显示，ID、来源等细节默认收起。Ctrl+O 展开或收起最近一个工具或命令卡片；命令卡片展开显示完整结果，工具输出预览仍受行数限制。推理正文不进入主界面。权限确认弹窗中的 Ctrl+O 查看该请求的预览，危险操作仍需输入完整的 yes，再按 Enter 批准。

状态行显示运行耗时与待发送消息数量，有会话目标时在同一行显示 Goal 状态和目标摘要。`/goal` 查看目标、状态与用量，设置、暂停、继续和清除直接更新状态行。底栏保留工作区、会话、上下文用量、权限模式、缓存指标和模型；有空间时显示快捷键提示。运行中按 Esc 中断，Ctrl+S 将当前输入作为即时引导；首次 Ctrl+C 会取消当前运行或清空草稿，并短暂显示退出提示，在 500ms 内再按一次退出。

TUI 在无法连接本进程 Host socket 而直接使用 Runtime 的兼容路径中，若当前会话仍有待发送消息，`/resume` 不会切到另一会话，也不会丢弃或转移这些输入。先在原会话处理完队列后再切换；恢复同一会话仍保留队列。正常 Host 的各会话独立持有 Runtime，不受此切换限制。回归入口见 `tests/runtime-queue-resume-ownership.test.ts`。

## 一次性任务

`run` 的模型、步数、权限和 headless 参数只作用于本次新会话，结束后释放临时运行实例；全局配置保持持久设置。取消绑定本次 run ID，超时与产物验收由 Host 执行。运行查询统一读取 SQLite 投影，对话和回合终态以 JSONL 为准。

```bash
biny run "阅读项目并总结入口模块" --permission-mode read-only --json
```

`--json` 输出机器可读的运行结果。读取终态、错误与验证结果来判断任务是否完成，不只检查是否有回答文本。

`--model <alias>` 临时指定已配置模型，`--max-steps <n>` 调整本次硬步数上限。`--headless` 关闭交互审批入口，不授予额外权限；`--isolated` 使用独立 Git worktree，需要工作区满足 Git 创建条件。

## 找到并恢复历史

```bash
biny sessions --json
biny sessions --limit 20 --json
biny resume <session-id>
```

分页查询返回下一页 cursor 时，使用 `biny sessions --cursor <cursor> --json` 继续。当前项目的列表不混入其他项目的会话。

Desktop 侧栏的项目和会话菜单可用上下键选择操作、Home/End 跳到首尾；Escape 关闭菜单并恢复原来的焦点。

新建项目时可以填写网站地址，Biny 会尝试读取 favicon 并显示在项目侧栏；读取失败不影响项目创建。项目目录仍由系统文件夹选择器确定。 打开或创建项目期间，如果通过菜单开始了另一任务或从终端交接了会话，较早发起的项目操作只保留项目入口，不覆盖较新的工作区和会话选择；已经创建的目录不会因此删除。 项目成功打开或创建并切换到空白草稿后，等待期间旧工作区已经发出的消息或斜杠命令仍可完成，但迟到回执不会重新选中旧会话或覆盖新工作区；取消或失败不会使等待期间已派发的当前工作区回执失效。

Desktop 项目会话先加载最近一页。展开项目并点击“显示更多”后，可用“加载更早会话”继续读取历史；每次只请求下一页，不改变当前会话。已加载且仍存在的会话会在项目刷新后保留并更新标题等信息。Cmd+K 搜索包含这些已加载会话；搜索框已打开时，新增或更新的已加载会话会刷新当前查询结果，不改变查询内容或输入焦点，也不重新扫描项目文件。这不代表扫描全部历史。

恢复后会继续使用原有历史。上下文压缩改变模型下一次看到的材料，不会删除原始会话历史。界面的标题、归档和置顶是管理元数据，不代表执行已经完成。Desktop 刷新工作区或重新打开时，侧栏置顶区域会载入所有已置顶会话，不受最近会话首屏分页限制；归档不会自动取消置顶。

重新生成回答时，会重新准备当前日期、文件记忆等本轮上下文，并保留目标回答之前的用户输入和已完成工具结果。临时上下文只进入本次模型请求，不追加重复用户消息，也不写入原始会话事件。

新的原生重试在准备完成后、正文模型或工具执行前保存独立的重试断点，绑定原输入、目标版本、消息槽与本次执行身份。此后暂停或异常退出可沿同一重试继续，复用已完成的工具结果；新的根输入或显式版本选择会阻止旧重试自动复活。准备阶段的辅助模型工作不在这个恢复边界内，缺少新重试身份的旧断点也不会按文字内容猜测归属。

回答提交使用实际运行结果保存收尾阶段，再依次提交回答、版本选择和运行终态。恢复只补齐已经确认的同一条回答，不把有正文当作任务完成。达到长度或预算上限的回答仍保留为选中版本；用户再次明确继续时使用新的回答身份，保留原任务及已有工具事实。完成后的消息父链独立保存全部执行上下文，不依赖继续保留断点。

## 分支与工作区隔离

Desktop 中从消息分支会创建新会话，保留分支点之前的对话上下文。新分支不会重放旧工具产生的文件修改、消息发送或其他外部操作。

会话分支与 Git worktree 是不同对象。Worktree 隔离代码检出；会话历史仍保存在原持久化根中。合并与清理须检查真实 Git 状态，不能由会话归档推断代码已经合并。

## 当前会话清单

`TodoWrite` 维护当前会话的完整清单，后续回合会再次读取，恢复会话后仍保留。后台读取晚到的结果（包括读取失败的空清单）不会覆盖切换会话、较新读取或已提交写入产生的当前清单。CLI 也可以查看和替换同一份清单：

```bash
biny todo show --session <session-id> --json
biny todo replace --session <session-id> --todos '[{"content":"检查结果","status":"pending"}]' --json
```

`biny todo show --json` 的 `sessionId` 是实际读取清单所属会话的完整 ID，可用于后续指定同一会话。

`--todos` 接受完整数组或含 `todos` 数组的对象；每次整份替换，不合并旧条目。条目需有非空文字，状态只能是 `pending`、`in_progress` 或 `completed`，最多一项进行中。不合法的输入会报错并保留原清单，不会跳过坏条目后保存剩余部分；显式传入 `[]` 仍会清空清单。清单状态只是工作记录，不替代实际执行和验证证据。

## 查看子代理执行

Desktop 在主对话内为每个子代理展示独立卡片，头部以简短任务描述为标题，例如“查设置页加载慢问题”；代理名称、实际模型和执行状态作为辅助信息。没有短描述的历史记录继续显示原名称。展开后可查看回答、思考和工具记录，历史自动加载；手动收起不会被新输出重新展开，收起后仅刷新状态。卡片没有消息输入或任务写操作。已读取的执行正文只在父工具结果的 Attempt 身份与所选记录一致时使用该结果作为缺失输出的回退；没有 Attempt 身份的旧结果仅在记录至多包含一次执行时保留兼容回退，不在多次执行间猜测归属。

执行正文在卡片内滚动。停在底部时跟随新内容，向上阅读时保留位置，可点“回到最新”恢复跟随。完整子执行记录保存在子会话中，界面展示不会把这些正文追加到父代理上下文。权限受阻、等待父代理处理授权和无响应等停止原因，见 [子代理执行预算与权限](CONFIGURATION.md#子代理执行预算与权限)。

## 导出与导入

```bash
biny session export <session-id> --format biny --out session.json --json
biny session import session.json --format biny --json
```

CLI 未指定 `--out` 时，导出写入当前目录；默认名称已占用时依次添加 `-1`、`-2` 等后缀，通过独占创建避免并发导出覆盖已有文件。前 1,000 个候选名称都被占用时停止并提示使用 `--out`。显式 `--out` 仍写入指定路径，会覆盖该路径已有文件。

Biny bundle 保存会话事件和可内嵌附件。附件源文件缺失或单个附件超过 50 MiB 时不内嵌，名称记入清单的 `skippedAttachments`，不使整份导出失败；权限或其他读取错误仍会中止导出。导出可能包含对话与业务资料，分享前按实际内容检查。

导入总是分配新的会话 ID；重复导入同一文件会产生不同会话。附件撞名时改名并更新引用。兼容格式只能保留该格式能表达的内容，不能当作全部运行事件的无损备份；可用格式见 `biny session import --help` 和 `biny session export --help`。

新导入的 Claude JSONL、Codex rollout 和 ChatGPT 会话使用独立的 Biny 消息身份，可用于日期详情、消息引用和分支。Claude 与 Codex 按导入顺序建立线性对话链，ChatGPT 只取明确活动分支；来源消息及父消息标识单独保留，不作为 Biny 的消息或分支身份。导入不会执行其中记录的工具操作，缺少调用 ID 的工具结果也不会猜测关联。

Desktop 的“设置 → 导入”可检测本机来源、选择 ChatGPT 导出 JSON，并管理模型设置、MCP 与会话的导入历史和同步。详细步骤见 [从其他应用导入](IMPORTS.md)。

工具调用与结果保留原始记录；缺少或重复的调用身份不用于建立消息树关联，也不按工具名或最近调用猜测归属。

新保存及导入附件的内部文件名会将连续点折叠成单点，并按 UTF-8 字节为实际前缀和 `.context` 后缀预留空间，使完整侧文件名不超过 255 字节。需要缩短时按完整字符截断，尽量保留扩展名；结构化附件仍保留原有安全化规则处理后的显示名。只保存路径的历史卡片可能显示规整后的文件名，例如 `report..pdf` 显示为 `report.pdf`；不会重命名已有文件。

导入附件保存到本次导入独占的批次目录，会话创建成功后才提交。导入失败时只清理能确认属于本次导入的文件；归属不明的替换文件或清理失败的内容会保留，错误中会显示原导入原因和实际残留路径，供手动处理。导入附件支持 Desktop 读取、模型输入和再次导出，不自动清理历史附件。

Desktop 发送或编辑图片、音频附件时会读取其实际内容。附件文件缺失或路径不安全时，会显示文件名并提示重新添加，不提交缺少该媒体内容的消息。

模型设置中的“图片输入”默认为“自动”：已声明支持的模型直接接收图片，能力未知时也允许尝试，实际支持情况以服务商响应为准；明确不支持时会在发送前提示。可选择“启用”覆盖不准确的目录信息，或选择“禁用”阻止图片输入；恢复“自动”会清除手动覆盖。开启此选项不会增加模型本身的视觉能力。音频输入仍要求模型明确支持。

## Host 连接中断与重连

短暂断线时，客户端保留等待中的运行结果和空闲观察，自动重连后继续同步。连续启动失败使自动恢复熔断时，这些本地等待会报错，空闲观察的事件订阅也会解除；恢复前新建的结果或空闲等待也会拒绝，不把缓存快照当作当前连接已经空闲的证据。本地观察失败不改变持久任务状态，Host 上的任务可能仍在运行。

Desktop 的显式重试会重置启动熔断，并让仍驻留的客户端重新连接。只有当前连接完成事件订阅、所需浏览器租约和快照同步后，才允许新的等待；只握手成功或其他客户端恢复都不够。已经报错的旧等待不会复活，重连本身也不重新提交旧任务。

连接与等待的实现见 [`RuntimeHostClient`](../src/runtime/host/client.ts) 的 `waitForIdle`、`stopConnectionRecovery` 和 `retryConnection`；Desktop 入口为 [`DesktopAgentManager.retryRuntime`](../src/desktop/electron/main/DesktopAgentManager.ts)。

## 中断与未知结果

重试若恰好在中间回答已保存、插话或排队消息尚未交付时退出，缺少真实终态就保持明确的未决状态，不猜测完成，也不自动重跑工具。检查已保存的回答和未交付消息后，再通过新输入继续。新输入从当前选中的可见历史开始；暂停后的空输入新回合也遵循这一选择，不会自动选中隐藏的重试版本或发送未交付消息。精确继续仍沿原重试的执行断点恢复。

Desktop 将已保存但未投递的插话或排队消息显示在只读恢复区域，正文与合法附件引用可选中复制。能确认属于非活动分支的记录会隐藏；不能确定原目标的记录单独标注“原目标未知”，不按时间或最近消息猜测归属。恢复展示不提供重发操作，不自动执行，也不改变原运行结果。

运行终态与工具结果分别保存。模型请求失败可以留下已经成功完成的工具操作；程序退出也不能证明远端操作没有发生。

恢复优先复用已持久化的工具结果。对于已派发但结果不明的写操作，缺少可信完成证据时停止并说明原因，不自动重放。收到 `unknown` 或不安全恢复状态时，先检查目标系统或实际文件，再决定后续操作。

长任务的暂停、继续、重试与验证见 [目标与自动化](AUTOMATION.md)。存储和写入者边界见 [架构](ARCHITECTURE.md#状态保存)。
