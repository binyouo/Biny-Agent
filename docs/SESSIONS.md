# 会话与恢复

会话保存对话、工具调用和运行结果。macOS Desktop、TUI 与 CLI chat 使用共享的本机 Runtime Host；一次性 `run` 也经由 Host 执行并输出任务结果。

## 一次对话如何留下记录

客户端提交输入后，Runtime Host 对目标会话进行准入并取得执行租约，AgentSession 组装上下文、请求模型并执行工具。所有用户消息、助手消息、工具调用、工具结果及错误事件均实时写入会话文件；客户端根据运行事件渲染增量内容。

| 数据类型 | 实际职责 |
| --- | --- |
| **Session JSONL** | 原始对话与工具事件，是重建历史与恢复运行的事实来源。 |
| **消息身份与父关系** | 确定对话链与分支点，严格按事件链路解析，不依展示顺序猜测。 |
| **Catalog** | 管理会话标题、置顶状态、归档与分支列表；归档不等于删除事件。 |
| **搜索与界面投影** | 针对查询与展示生成的本地缓存投影，可重建；投影缺失不代表原始会话丢失。 |
| **断点、租约与运行记录** | 记录执行阶段、写入所有权与阶段性结果，用于中断恢复与重试判断。 |

### 写入租约与执行所有权

同一会话的写入严格受租约约束，多个客户端连接不会各自成为独立写入者。恢复流程会同时读取历史事件与执行状态，重建下一轮所需的上下文，并核对工具是否已派发、结果是否可信。历史事件、回合终态与任务验收分别保存，不能仅凭助手的文本回答推断整段执行已完成。

### 任务产物与范围验收

在配置了命令验收的任务中，系统会核对声明的产物路径（`artifactPaths`）与验收依赖（`definitionPaths`），防止在产物或验收标准改变后误用过时结果：
- **修改范围检查**：任务执行期间，修改指定文件或声明目录内的文件均计入检查；生成范围外的测试报告或临时文件不会阻断任务。允许为新文件创建父目录，但不允许修改已有父目录的权限。
- **基线更新要求**：目录范围规则升级后，缺少新版基线的未完成任务不会自动续跑或套用旧验收，需新建任务重新建立基线；已有产物保留，已完成的历史记录不改写。
- **检查边界**：此项属于任务执行后的状态比对检查，并非文件系统沙箱，亦不会回滚已经落盘的文件修改。

### 时间与日期感知

- **消息发送时间与时区**：模型读取历史时，会收到每条用户消息发送时的原始本地时间与时区，用于准确理解“今天”、“明天”等相对表达。旧消息若缺失时区信息则明确标记为未知，不按当前系统时区臆造。时间说明仅注入模型上下文，聊天正文与历史记录保持原样。
- **动态日期注入**：每次模型请求前均会读取当前本地日期；若上下文未记录日期，或日期、时区、UTC 偏移发生改变，会在消息末尾自动追加日期说明。工具调用循环跨过午夜时，下一次请求即可感知新日期。初始请求为日期注入预留独立预算，不随 Activity 等辅助材料被裁剪；追加的日期说明不写入持久化聊天事件。

## 客户端与接入入口

| 入口 | 用途与定位 |
| --- | --- |
| **Desktop** | 原生 macOS 桌面端，查看项目与聊天，处理文件附件、工具授权与多模态交互。 |
| **`biny` / `biny chat` / `biny tui`** | 终端对话环境，在当前项目内开启交互式 TUI 或 Chat。 |
| **`biny run "任务"`** | 命令行非交互式执行，适合脚本化或一次性批处理任务。 |
| **`biny resume`** | 从终端交互式列表中选择历史会话并恢复。 |

CLI 以启动时的当前目录作为工作区，同名但路径不同的项目拥有独立的会话分区。跨项目检索原始对话使用：

```bash
biny history search "关键词"
```

检索结果会显示来源文件路径，方便区分不同项目的同名会话。全文索引缓存保存在 `search/sessions-v2.sqlite`；首次使用需从 JSONL 建立索引，支持分批构建与取消，不会改写原始会话。

命令行还可以直接管理会话元数据或检查工具状态：
- **元数据管理**：`session rename/pin/unpin/archive/unarchive/duplicate/delete`。
- **连接 Host**：`session create/usage/compact`。
- **本地记录与工具**：`session messages/search` 读取消息分支，`tool list/call` 查询目录或经 Host 执行工具。更多参数与分页说明见 [CLI 使用指南](CLI_USAGE.md#会话用量与工具)。

## Desktop 核心交互

### 快速搜索（⌘K / Ctrl+K）

按 `⌘K`（Windows / Linux 为 `Ctrl+K`）唤出快速搜索面板，可在项目、任务与当前项目文件之间即时跳转：
- **即时检索与复用**：输入至少 2 个字符后开始检索项目文件，短时间内的重复查询直接复用缓存结果。
- **状态提示与重试**：文件扫描未完成时会显示提示；若扫描中断可使用原查询重试，已加载的项目与任务依然可直接打开。
- **上下文保护**：搜索期间切换项目会自动重置查询，避免误选旧项目文件；在同项目内更新任务列表不会清空查询。关闭搜索面板后，焦点自动交还给唤出入口。

### 输入区对象引用（@）

在输入框中键入 `@` 可在当前项目内快速检索并引用对象：
- **快速匹配与预览**：输入 `@<关键词>`（例如 `@readme`）即时列出匹配项，文件名旁标明所在目录，方便区分同名文件。亦可输入 `@文件：` 等前缀限定检索类型。
- **键盘导航**：按 `↑` / `↓` 移动选择候选，按 `Enter` 在光标处插入短标签；按 `Esc` 关闭候选菜单。候选菜单打开但没有匹配项时，按 `Enter` 不会误发消息。
- **引用解析与核对**：支持引用当前会话的消息、工具调用与片段，或跨会话引用其他聊天。插入短标签后继续打字不会唤出侧栏，点击标签可查看引用详情。草稿中仅保留引用的 URI，发送时再物化为完整正文。消息菜单中的“查看引用来源”仅展示当前导航内最近一次查询的结果。

### 历史消息编辑

Desktop 支持对已发送的历史消息进行二次编辑：
- **独立草稿保存**：编辑历史消息使用独立的临时草稿，不覆盖未发送的普通草稿；提交期间输入区暂时锁定。
- **安全失败回退**：编辑提交失败时保留当前修改文本，便于重试；提交成功后退出编辑状态并恢复未发送的普通草稿。
- **导航防干扰**：等待回执期间切换会话或转去编辑其他消息，旧请求不会强行切回原聊天或关闭新的编辑框；取消编辑仅退出当前视图，不撤销已提交的 Runtime 请求。实现细节见 [`App.tsx`](../src/desktop/renderer/src/App.tsx) 与 [`Composer.tsx`](../src/desktop/renderer/src/components/Composer.tsx)，回归测试见 [`message-edit-navigation-scope.test.ts`](../tests/message-edit-navigation-scope.test.ts)。

### 运行中排队与即时补充（Steer）

当 Agent 正在执行任务时，输入区支持两种不同意图的操作：
- **排队后续消息（`Enter`）**：在运行状态下按 `Enter`，消息会加入待发送队列，待当前回合结束后按序自动发送。在空输入框中按 `↑` 可编辑队尾的排队消息，按 `Enter` 保存修改，按 `Esc` 取消编辑。
- **即时补充本轮（`⌘ Enter` / `Ctrl+Enter`）**：在执行中需要向模型即时补充指引或干预时，按 `⌘ Enter`（Windows / Linux 为 `Ctrl+Enter`）直接插话。时间线先显示“待补充本轮”，正式投递后显示“补充本轮”。已提交的补充不支持原地修改，如需更正可再次发送补充。
- **未投递消息的只读恢复**：任务运行结束或中断后，若仍有未投递的排队或插话消息，会在底部只读恢复区域完整显示，方便用户直接选中复制正文与附件引用；界面不自动重发，亦不改写历史。

### 会话与项目管理

- **新建任务与草稿隔离**：在顶栏切换项目时，输入区平稳切到目标项目的草稿；文本、引用与处理中的附件均保留在原项目中，切回后可继续使用。回归测试见 [`new-task-attachment-project.test.ts`](../tests/new-task-attachment-project.test.ts)。
- **会话平滑切换**：连续切换会话以最后一次选择为准，无需等待前一次读取或转场动画完成；同项目内的会话共用后台 Host，离开当前会话后正在运行的任务继续在后台执行。
- **侧栏项目移除**：点击侧栏“移除项目”仅移除项目入口，不删除任何项目文件或历史记录。若移除当前项目，界面平滑转至后备空白页，未发送草稿不跨项目迁移。
- **会话删除与多选**：
  - 悬停或键盘聚焦会话行时显示删除按钮，点击变为红色确认，再次点击执行；按 `Esc`、移开焦点或等待 3 秒自动取消；按住 `Shift` 点击可直接删除。
  - 右键选择“多选”可跨文件夹批量勾选会话，顶部显示选中数量并支持一次性确认删除。
  - 删除无法撤销（不删除工作区项目文件）；运行中的会话须先停止任务。确认后会话行动画淡出，后台异步清理索引，不阻塞继续操作其他会话。

## 终端对话（TUI 与 CLI Chat）

在目标项目根目录下运行 `biny tui` 或 `biny chat` 即可开启终端对话。

### 基础输入与状态呈现

- **输入与命令补全**：输入框边框颜色随 thinking level 实时变化；键入 `/` 唤出命令菜单，按 `Tab` 补全候选，按 `Enter` 发送消息或确认命令。必填参数命令会留在输入框中等待补齐。
- **技能与子代理选择**：
  - 输入 `/skills` 打开可搜索的技能选择器；选择后技能名称填入草稿，保留已有正文，补充任务后按 `Enter` 发送。
  - 输入 `/subagent` 提供子代理任务状态、定义、启动与取消入口。
- **工具卡片折叠与展开（Ctrl+O）**：连续工具调用紧凑显示，内联命令卡片摘要最多 8 行。按 `Ctrl+O` 展开或收起最近的工具或命令卡片（展开显示完整结果，工具输出预览仍受行数限制）。权限确认弹窗中按 `Ctrl+O` 可预览请求详情。推理正文不进入主界面。

### 快捷控制与状态行

- `Esc`：中断当前运行。
- `Ctrl+S`：将当前输入框内容作为即时引导（Steer）注入运行中轮次。
- `Ctrl+C`：首次按压取消当前运行或清空草稿并弹出退出提示，500ms 内再次按压退出应用。
- `/goal`：管理长期目标；状态行同步显示运行耗时、排队消息数、Goal 状态与目标摘要。
- **队列保护**：在直接使用 Runtime 的兼容路径中，若当前会话仍有待发消息，须先在原会话处理完队列才能通过 `/resume` 切换会话，防止排队输入丢失。回归测试见 `tests/runtime-queue-resume-ownership.test.ts`。

## 一次性任务（biny run）

`run` 命令用于执行非交互式任务，运行结束后自动释放临时运行实例，不修改全局持久配置：

```bash
biny run "阅读项目并总结入口模块" --permission-mode read-only --json
```

常用选项：
- `--json`：输出机器可读的运行结果。通过终态、错误与验收结果判断任务是否完成，而非仅核对文本。
- `--permission-mode <mode>`：指定本次任务的权限模式（如 `read-only`、`full`）。
- `--model <alias>`：临时指定本次运行的模型别名。
- `--max-steps <n>`：设置本次任务的硬步数上限。
- `--headless`：关闭交互审批入口（不自动授予额外权限）。
- `--isolated`：使用独立的临时 Git worktree 执行任务，需工作区满足 Git 提交条件。

## 历史恢复与重试断点

```bash
biny sessions --json
biny sessions --limit 20 --json
biny resume <session-id>
```

### 侧栏历史与浏览

- **分页加载**：Desktop 侧栏会话先加载最近一页。点击“显示更多”后可用“加载更早会话”继续读取；每次只请求下一页，不影响当前会话。
- **置顶区域**：刷新或重新打开工作区时，侧栏置顶区域会自动载入所有已置顶会话，不受常规分页限制；归档会话不会自动取消置顶。
- **项目创建与图标**：新建项目时填写网站地址会尝试获取 favicon 并显示在侧栏，获取失败不影响创建。项目目录由系统选择器决定。

### 回答重新生成与原生断点

- **重新生成上下文**：重新生成回答时，会重新准备当前日期、文件记忆等本轮动态上下文，同时保留目标回答前的用户输入与已完成工具结果，避免追加重复消息。
- **原生重试断点**：在准备完成、正文模型或工具执行前，系统会保存独立的重试断点（绑定原输入、目标版本、消息槽与本次执行身份）。若任务暂停或异常退出，可沿同一断点继续恢复并复用已完成的工具结果；若用户提交新输入或显式切换版本，则旧重试不会自动复活。
- **终态确认与收尾**：回答提交使用实际运行结果保存收尾阶段，依次确认回答、版本选择与终态。达到长度或预算上限的回答仍保留为选中版本；用户再次继续时会分配新回答身份，保留原任务与已有事实。

## 分支与工作区隔离

- **消息分支**：在 Desktop 中基于历史消息派生分支会创建新会话，完整保留分支点之前的对话上下文。新分支不会重放旧工具产生的外部文件修改。
- **会话分支与 Git Worktree 的区别**：会话分支仅作用于对话历史；若需要隔离实际代码修改，须使用 Git worktree。

### 工作树隔离任务

通过 Desktop 项目菜单的“新建隔离任务”、终端中的 `/new --isolated`，或命令行的 `biny run --isolated "任务"` 均可创建独立工作树：
- **隔离机制**：基于当前分支已提交的 HEAD 检出独立工作树，不复制未提交的本地改动或被忽略文件。
- **生命周期与合并**：隔离任务结束后工作树目录保留；合并与清理前须核对真实 Git 状态与 squash 源提交证据。若工作树目录被误删，系统会阻止恢复执行，需先恢复目录。子代理的临时工作树规则见 [子代理](EXTENSIONS.md#子代理)。

## 当前会话清单（Todo）

`TodoWrite` 工具用于维护当前会话的任务清单，后续轮次会自动读取，会话恢复后依然保留。亦可通过 CLI 查看或替换：

```bash
biny todo show --session <session-id> --json
biny todo replace --session <session-id> --todos '[{"content":"检查构建产物","status":"pending"}]' --json
```

- `--todos` 接受完整任务数组或含 `todos` 字段的对象，每次为整份替换。
- 任务条目必须包含非空文字内容，状态可选：`pending`（待办）、`in_progress`（进行中，最多一项）、`completed`（已完成）。
- 传入非法格式会明确报错并保留原清单；显式传入 `[]` 则清空清单。清单仅为工作状态记录，不替代实际执行证据。

## 查看子代理执行

Desktop 在主对话流中为每个子代理提供独立卡片：
- **卡片摘要**：头部以简短任务描述为标题（例如“排查设置页加载慢问题”），副标展示代理名称、执行模型与当前状态。
- **展开详情与滚动**：展开后可查看回答正文、思考过程与工具调用。内容在卡片内独立滚动；停在底部时自动跟随新输出，向上滚动阅读时锁定位置，点击“回到最新”恢复自动跟随。
- **安全隔离**：子代理卡片不包含消息输入框；其完整执行记录保存在子会话中，主对话不会把子代理的全量正文追加到父代理上下文。权限与预算规则见 [子代理执行预算与权限](CONFIGURATION.md#子代理执行预算与权限)。

## 会话导入与导出

### 复制与导出

- **剪贴板复制**：Desktop 消息菜单提供“复制为 Markdown”（严格保留代码和 JSON 字符串中的 `U+00A0` 不换行空格字面值）与“复制为纯文本”。
- **CLI 导出与导入**：

```bash
biny session export <session-id> --format biny --out session.json --json
biny session import session.json --format biny --json
```

未指定 `--out` 时默认导出到当前目录，若名称已被占用会自动追加 `-1`、`-2` 等后缀避免覆盖。

### Biny Bundle 格式

- **原生 Bundle**：完整保存会话事件与可内嵌附件。单个附件不超过 50 MiB 时直接内嵌；超出限制的附件名称记录在清单的 `skippedAttachments` 中，不导致整份导出失败。
- **记忆策略保留**：原生 Bundle（版本 4）会保存该会话单独配置的“使用记忆 / 贡献记忆”覆盖策略，导入后依然生效；无覆盖的包使用版本 2 格式。
- **外部格式兼容**：支持导入 Claude JSONL、Codex rollout 与 ChatGPT 导出 JSON。导入后会分配全新的 Biny 会话与消息 ID，建立线性对话链或活动分支；详见 [从其他应用导入](IMPORTS.md)。

### 附件规整与多模态输入

- **附件文件名规整**：新保存与导入的附件会自动将连续点折叠为单点，并预留前缀与后缀空间，确保完整文件名不超过 255 字节，超长时按字符完整截断并尽量保留扩展名。
- **媒体内容检查**：发送或编辑图片、音频附件时会校验实际文件存在且路径合法，防止提交空引用。
- **多模态模型设置**：模型设置中的“图片输入”默认为“自动”（已声明支持的模型直接接收，未知时允许尝试；明确不支持时在发送前提示），亦可手动“启用”或“禁用”；音频输入仍要求模型明确支持。

## Host 连接中断与重连

Desktop 与终端通过本地 Runtime Host 通信。若连接短暂中断，客户端会保留等待中的运行结果并在后台自动重连：
- **自动恢复与熔断**：连续启动失败会触发自动恢复熔断，此时等待中的任务会报错并解除事件订阅，避免将过时快照误判为空闲。
- **显式重试**：Desktop 的重试操作会重置熔断并重新建立连接；只有连接完成事件订阅、租约与快照同步后才允许接受新等待。连接恢复见 [`RuntimeHostClient`](../src/runtime/host/client.ts) 与 [`DesktopAgentManager.retryRuntime`](../src/desktop/electron/main/DesktopAgentManager.ts)。

## 中断与未知结果处理

- **未决状态保护**：重试若在模型回答已保存、但排队消息尚未送达时中断，系统会保持明确的未决状态，不臆测任务完成，亦不自动重跑工具。新输入会从当前选中的可见历史开始，精确继续沿原执行断点恢复。
- **工具写操作确认**：恢复流程优先复用已持久化的工具结果；对于已派发但结果不明的外部写操作，在缺少可信完成证据时会停止并报错，不自动盲目重放。
- 长任务暂停、继续与验证说明见 [目标与自动化](AUTOMATION.md)，存储与写入者所有权见 [架构](ARCHITECTURE.md#状态保存)。

### 模型请求前缀

在同一驻留会话中，已发送的参考材料与工具结果会保留其模型上下文投影，下一轮请求不因回合结束而清除这些前缀。工作区快照与 RepoMap 由运行时消息动态维护，工具清单、Todo、Goal 与情绪在发生状态变更时追加快照：
- **缓存连续性**：压缩会话、编辑重试、切换模型或权限、修改项目规则与技能目录均可能触发前缀重建。
- **Prompt Cache 边界**：冷启动或会话恢复时会从原始事件重建临时资料，形成新的缓存边界。实际缓存命中情况仍取决于 Provider 的协议、有效期和路由策略。
