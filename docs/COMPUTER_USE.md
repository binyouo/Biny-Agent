# Computer Use

Computer Use 用于观察和操作 macOS 原生应用。Desktop 通过内置 MCP 提供受控工具；外部客户端可以启动独立 MCP 服务，直接 `biny cu` 命令则供本机用户显式调用。

## 观察与输入的执行链路

Desktop 工具经 MCP 协议交给现有桌面执行服务，再由同一个 Controller、原生 driver 与 macOS helper 执行辅助功能读取、窗口捕获及输入，不启动第二套桌面控制器。Controller 管理启用状态、会话所有权、应用授权、当前观察与取消；helper 完成系统调用并返回结果。系统权限与 Biny 应用授权在不同层检查。

观察结果绑定精确 PID、窗口、捕获身份、截图尺寸及可用控件 token。输入需要使用当前有效的观察，并在派发前再次确认目标与授权；切换控制状态、撤销授权或取消会使旧观察失效。坐标与控件引用描述一次观察中的目标，不能作为跨窗口或跨进程的永久地址。

| 资料 | 用途与生命周期 |
| --- | --- |
| 模型观察结果 | 为下一次输入提供目标与控件依据，按 Controller 状态失效。 |
| 监督预览 | 临时显示目标画面，像素刷新不改写观察凭据，不进入活动历史作为记录。 |
| 窗口镜像 | 独立捕获与监听会话，关闭或连接结束时释放所属资源。 |
| 动作日志 | 开启后保存动作类型、目标、耗时和结果等本地元数据。 |

动作有未派发、已完成和结果未知等结果边界。系统调用已经派发后发生取消或断线，不能把它解释为没有操作目标，也不能自动重复动作。

## 开启与系统权限

新配置的 Computer Use 默认开启，已有关闭配置保持关闭。这个开关只保存使用意图，不会在首次请求前自动启动 helper、截图或申请系统权限。在 Desktop 的“设置 → Computer Use”管理开关，并按设置页引导授予 macOS 辅助功能和屏幕录制权限。

辅助功能用于读取控件与操作，屏幕录制用于捕获窗口。授权其中一项不代表另一项可用；应用重新构建后系统可能需要重新确认授权。先在设置页测试，失败时根据实际权限状态重试。

```bash
biny cu status --json
biny cu doctor --json
```

这些命令检查原生 helper 与系统能力。它们通过不代表某个目标应用已获产品授权。

## 应用审批

应用授权在“设置 → Computer Use”管理，并跨会话保存。严格审批默认关闭，首次使用应用时自动保存授权；开启严格审批后，只允许已批准应用，通用工具的自动批准不覆盖此条件。

```bash
biny computer status --json
biny computer strict on --json
biny computer approve <bundle-id> --json
biny computer revoke <bundle-id> --json
```

批准和撤销操作针对已发现的应用记录。`bundle-id` 标识应用，PID 标识当前运行实例；不能用旧 PID 推断当前应用身份。审批存储错误、身份无法确认或目标冲突时停止执行。

撤销影响后续观察与输入，不能撤回已经派发的动作。记录只保存应用授权与使用元数据，不保存输入正文或截图。

## 观察再操作

内置 MCP 名为 `computer-use`，由 Desktop 工作区 Runtime 自动连接，以进程内传输完成 MCP 初始化、工具发现、调用和取消。在“设置 → MCP”可查看连接状态和工具列表，不需要手工添加命令；启用和应用授权仍在 Computer Use 设置中管理。启动 Desktop 或切换到项目后，当前项目自动启动 Runtime 并连接已启用的 MCP，不必先发送消息或点击连接。当前项目保持连接；切换项目后原 Host 可在没有后台工作时空闲回收。短暂“待连接”或“连接中”不禁用普通消息发送；失败时可手动重连。

MCP 的“已连接”只表示工具协议就绪，不表示桌面控制已启用或系统权限已授予。实际列窗口、截图和输入前，仍须在 Computer Use 设置中启用功能并满足对应应用授权与 macOS 权限。

工具包括 `ComputerList`、`ComputerLaunch`、`ComputerObserve`、`ComputerAction` 与 `ComputerMirror`，来源为 MCP。调用使用当前 Agent 会话身份；端点替换后旧工具调用拒绝执行，连接结束释放所属控制资源。输入使用当前有效观察结果中的精确应用、窗口和控件引用；预览画面用于监督，不能代替模型观察凭据。

未启动应用先按应用标识调用启动工具，通过审批后请求后台启动，再查询和选择窗口。观察工具需要已运行的准确窗口，不能凭旧进程编号启动应用。后台启动不保证目标应用自身不会改变焦点。

滚动可使用控件引用或当前截图内的完整坐标，因此没有无障碍控件的自绘界面也能指定滚动位置。每次观察在原生层绑定调用方、进程、窗口和有效期；不同客户端互不覆盖控件引用与坐标映射。模型输入凭据六十秒过期且只能消费一次。

系统明确拒绝的输入报告未执行；无障碍接口成功表示操作已接受，不代表业务结果已经达成。物理输入已投递后仍须根据返回的新观察核对业务结果，不自动重放。动作后观察失败时，可只读重新观察恢复；请求超时、取消或断线导致执行情况未知时，当前轮停止输入，用户恢复任务后先观察。用户主动暂停、接管和停用仍须由用户恢复。自动观察的临时截图在读取完成或失败后删除，迟到回包也会清理。

直接 CLI 可以先列窗口，再观察指定目标：

```bash
biny cu windows <pid> --json
biny cu snap <pid> --window <window-id> --json
biny cu click --pixel 120 80 --pid <pid> --window <window-id> --json
```

PID 和窗口 ID 使用当前返回值。输入方式、控件可写性和窗口存在性按本次观察确认，不复用另一个窗口的引用。动作取消或结果不明时，先重新观察，不自动重复输入。

直接 CLI 的物理点击、拖拽及像素右键需要显式传 `--window`。缺少精确窗口或窗口局部投递能力时拒绝，不再使用首个窗口或全局鼠标作为回退；`--window` 只指定目标，不隐式请求前台输入。

没有可用 AX 控件的自绘界面仍可按截图点击，并向已聚焦输入框输入文字。内置 `ComputerAction` 的 `type_text` 在 `auto`、`physical`、`unicode` 模式下不要求 `elementToken`；`ax` 模式才要求可写控件引用。所有模式仍要求同一准确窗口的有效 `captureId`。

后台是默认投递方式。后台物理点击和拖拽绑定准确窗口，使用窗口局部事件向目标进程投递，不走全局鼠标输入，也不主动隐藏、移动或还原用户鼠标。后台动作期间启用按目标进程限定的激活事件拦截；拦截不可用或无法确认窗口局部投递能力时拒绝动作，不回退到全局事件。点击后保留目标应用内部的新控件焦点，不把它还原到点击前。

需要前台输入时，用户须在设置里开启“允许明确批准的前台动作”，工具再明确选择 `delivery: "foreground"`。观察结果的 `foregroundAllowed` 表示此许可；开启、撤销后旧观察失效。原生层激活并核对准确目标窗口，无法确认聚焦目标时停止输入，不自动从后台失败升级到前台。

输入回执中的“效果待核对”表示调用已结束，但尚未确认业务结果，不作为调用失败或执行中断。系统保留原生警告，并返回动作后的截图与新观察凭据。模型直接核对输入框、结果页或播放条；信息足够时继续下一步，不额外观察，也不重放刚才的动作。没有可用画面时先重新观察。独立外部服务的动作回图不含新凭据，下一次输入前仍须重新观察。自绘应用的中文输入、真实后台焦点和不同 macOS 版本的拦截效果仍需人工核对，工具派发完成不代表目标已经接收。

## 按窗口镜像

```bash
biny cu pip open <window-id> --pid <pid> --json
biny cu pip open <window-id> --pid <pid> --on-minimize --json
biny cu pip list --json
biny cu pip close --all --json
```

普通镜像实时显示指定窗口；`--on-minimize` 先监听，在源窗口最小化时显示，不激活或恢复源窗口。列表返回会话状态与 `last_frame_age_ms`；没有收到帧时帧龄为 `null`，最后画面不能证明当前仍在更新。

关闭会话释放捕获和监听。内置 `ComputerMirror` 沿用应用审批。Desktop 将浏览器与电脑监督画面放在统一 PiP 中，可切换来源、关闭单项并返回聊天；预览默认开启，开关与布局跨重启保存。

统一监督预览不是置顶窗口，也不跨 Spaces 或全屏常驻。首次打开不激活，帧刷新不重新显示或提升窗口；可以移到旁边或让其他窗口覆盖它。“关闭此项”收起画面，不等于停止正在执行的任务；暂停、人工接管和停止使用对应按钮。

## 文本输入

```bash
biny cu type_text "ABC" --pid <pid> --input-method physical --json
```

`physical` 按当前键盘布局规划整个文本。布局无法表示的字符会在输入前拒绝，不静默改走 Unicode。`auto`、`unicode` 与 `ax` 是另外的输入选择；`ax` 需要有效的可写控件引用。以返回的实际路线和重新观察结果判断输入是否送达。

## 外部 MCP

stdio 入口：

```bash
biny computer mcp
```

在客户端配置命令 `biny` 和参数 `["computer", "mcp"]`。stdout 传输 MCP 协议。

本地 HTTP 入口：

```bash
biny computer mcp --http --port 0
```

输出包含 `url` 与 `tokenPath`。客户端从私有令牌文件读取值，以 `Authorization: Bearer <token>` 鉴权；服务监听本机回环地址。正常关闭时删除由本次服务创建的令牌文件，不能把强制终止当作清理已经完成。

外部 MCP 保留独立连接。发现 Desktop 控制服务后，观察、启动、输入和镜像均交给同一个桌面控制器，遵守会话占用、暂停、接管和应用审批；已连接的 Desktop 中断时拒绝继续，不切换到独立输入。未运行 Desktop 时使用独立原生服务，仍检查全局开关、持久化审批和观察有效期；每次输入消费观察，下一次输入前重新观察。多个窗口时须显式选择窗口。断开会释放该连接拥有的桌面控制资源。

## 直接入口与日志

`biny cu` 是用户显式调用的直接原生入口，不经过产品应用审批与观察凭据校验。它受 macOS 权限与原生命令自身校验约束；Agent 不能用这个入口绕过已被拒绝的工具操作。

Agent 的 `Bash` 不作为桌面控制回退。macOS 下即使文件写入限制关闭，仍限制 AppleEvents、HID、辅助功能与 WindowServer 访问，并阻止连接已知原生 helper socket；直接调用 `biny cu` 或启动原生控制 MCP 也会被拒绝。普通文件命令和无关本地 IPC 不因此禁用。这不是任意外部服务的隔离保证：其他已授权远程服务仍按各自权限边界管理。

操作日志按需开启，只保存本地动作元数据。窗口附件快捷键见 [活动记录与 Appshots](ACTIVITY.md#appshots)，通用授权说明见 [工具与权限](PERMISSIONS.md)。
