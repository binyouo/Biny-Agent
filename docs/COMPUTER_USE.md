# Computer Use

Computer Use 用于观察和操作 macOS 原生应用。Desktop 通过内置 MCP 提供受控工具；外部客户端可以启动独立 MCP 服务，直接 `biny cu` 命令则供本机用户显式调用。

## 观察与输入的执行链路

Desktop 工具经 MCP 协议交给现有桌面执行服务，再由同一个 Controller、原生 driver 与 macOS helper 执行辅助功能读取、窗口捕获及输入，不启动第二套桌面控制器。Controller 管理启用状态、会话所有权、应用授权、当前观察与取消；helper 完成系统调用并返回结果。系统权限与 Biny 应用授权在不同层检查。

观察结果绑定精确 PID、窗口、捕获身份、截图尺寸及可用控件 token。控件行集显示可用的标题或描述，并标识已聚焦和停用状态。输入需要使用当前有效的观察，并在派发前再次确认目标与授权；切换控制状态、撤销授权或取消会使旧观察失效。坐标与控件引用描述一次观察中的目标，不能作为跨窗口或跨进程的永久地址。

| 资料 | 用途与生命周期 |
| --- | --- |
| 模型观察结果 | 为下一次输入提供目标与控件依据，按 Controller 状态失效。 |
| 监督预览 | 临时显示目标画面，像素刷新不改写观察凭据，不进入活动历史作为记录。 |
| 窗口镜像 | 独立捕获与监听会话，关闭或连接结束时释放所属资源。 |
| 动作日志 | 开启后保存动作类型、目标、耗时和结果等本地元数据。 |

动作有未派发、已完成和结果未知等结果边界。系统调用已经派发后发生取消或断线，不能把它解释为没有操作目标，也不能自动重复动作。

原生组件意外退出时，Desktop 会停用控制并撤销旧观察；在途输入的结果按未知处理。重新启用后须重新观察。组件正常空闲退出后，会在下次需要时重新启动。

## 开启与系统权限

新配置的 Computer Use 默认开启，已有关闭配置保持关闭。这个开关只保存使用意图，不会在首次请求前自动启动 helper、截图或申请系统权限。在 Desktop 的“设置 → Computer Use”管理开关，并按设置页引导授予 macOS 辅助功能和屏幕录制权限。

辅助功能用于读取控件与操作，屏幕录制用于捕获窗口。授权其中一项不代表另一项可用；应用重新构建后系统可能需要重新确认授权。打开设置页会检查并按需启动组件，页面显示期间约每 15 秒刷新组件与权限状态，但不会申请权限、截图或输入。在设置页请求辅助功能授权后，页面会约 2.5 秒后再次读取权限，也可点击“刷新”。先在设置页测试，失败时根据实际权限状态重试。

```bash
biny cu status --json
biny cu doctor --json
```

这些命令检查原生 helper 与系统能力。它们通过不代表某个目标应用已获产品授权。

## 应用审批

应用授权在“设置 → Computer Use”管理，并跨会话保存。严格审批默认关闭，首次使用应用时自动保存授权；开启严格审批后，只允许已批准应用，通用工具的自动批准不覆盖此条件。
应用授权列表显示使用次数和最近使用时间，可从列表刷新授权信息；撤销仍需要确认。

```bash
biny computer status --json
biny computer strict on --json
biny computer approve <bundle-id> --json
biny computer revoke <bundle-id> --json
```

批准和撤销操作针对已发现的应用记录。`bundle-id` 标识应用，PID 标识当前运行实例；不能用旧 PID 推断当前应用身份。审批存储错误、身份无法确认或目标冲突时停止执行。

撤销影响后续观察与输入，不能撤回已经派发的动作。记录只保存应用授权与使用元数据，不保存输入正文或截图。

## 观察再操作

内置 MCP 名为 `computer-use`，由 Desktop 工作区 Runtime 自动连接，以进程内传输完成 MCP 初始化、工具发现、调用和取消。在“设置 → MCP”可查看连接状态和工具列表，不需要手工添加命令；启用和应用授权仍在 Computer Use 设置中管理。启动 Desktop 或切换到项目后，当前项目自动启动 Runtime 并连接已启用的 MCP，不必先发送消息或点击连接。当前项目保持连接；切换项目后原 Host 可在没有后台工作时空闲回收。短暂“待连接”或“连接中”不禁用普通消息发送；失败时可手动重连。

macOS 的终端 Agent Runtime 也自动连接 `computer-use`，使用全局 `computer.enabled` 开关，默认开启，无需在每个项目添加 MCP。独立终端连接使用本地进程内服务，工具名称沿用外部 MCP 的 `list_apps`、`get_app_state`、`click` 等；每个 Agent 会话拥有独立的观察与控制连接。服务发现正在运行的 Desktop 后会使用其控制器，不要求 Desktop 先打开相同项目；接入后的中断仍拒绝继续输入。未运行 Desktop 时遵守独立服务的限制，见[外部 MCP](#外部-mcp)。显式配置的同名 MCP 优先，停用选项不会被默认连接覆盖。建立 MCP 连接不会自动发起屏幕采集或输入，原生 helper 按实际调用启动。

终端 Agent 使用 `computer-use` MCP 观察或操作时，返回的截图通过图片通道交给当前模型，并与其他观察共享近期图片预算；会话持久记录不包含图片数据。图片无法交付时，工具结果要求重新观察；已经派发的动作不得直接重放。

MCP 的“已连接”只表示工具协议就绪，不表示桌面控制已启用或系统权限已授予。实际列窗口、截图和输入前，仍须在 Computer Use 设置中启用功能并满足对应应用授权与 macOS 权限。

工具包括 `ComputerList`、`ComputerLaunch`、`ComputerObserve`、`ComputerAction`、`ComputerSequence` 与 `ComputerMirror`，来源为 MCP。调用使用当前 Agent 会话身份；端点替换后旧工具调用拒绝执行，连接结束释放所属控制资源。输入使用当前有效观察结果中的精确应用、窗口和控件引用；预览画面用于监督，不能代替模型观察凭据。

应用列表包含运行中的应用和近期使用过的应用。原生列表附带当前前台状态；CLI 用 `*` 标出前台应用、`R` 标出其他运行应用，系统提供使用次数时显示次数，未知时留空。系统提供时，列表会附带最近使用时间和系统使用次数；它们与设置页记录的桌面控制授权使用次数分别统计。

关闭会话运行时、重建同一会话或切换新草稿时，会收回旧实例的观察凭据与桌面控制权；重建后须重新观察。恢复失败时，已放弃的旧会话资源同样清理；尚未切换时保留原会话。工作区内其他会话继续复用 MCP 连接和原生服务，不因单个运行时退出而重连全部工具。清理失败会报告错误，不视为已释放控制权。普通页面切换和回合结束不销毁仍在使用的运行时。

未启动应用先按应用标识调用启动工具，通过审批后请求后台启动，再查询和选择窗口。预览开启时，启动后监督窗会等待目标应用出现窗口，并展示该应用的一个可用窗口；它不会生成输入凭据。观察工具需要已运行的准确窗口，不能凭旧进程编号启动应用。后台启动不保证目标应用自身不会改变焦点。

未指定窗口的原生观察优先选择唯一的聚焦窗口，否则选择唯一可用窗口；控件树、截图和观察凭据绑定同一窗口。外部 MCP 使用同一选择规则，并最多等待五秒让窗口出现；多个窗口且焦点不明确，或同一应用有多个运行进程时需要明确选择。超时会报告窗口尚未就绪，不重复启动应用。观察结果的进程和窗口必须与请求目标一致。

滚动可使用控件引用或当前截图内的完整坐标，因此没有无障碍控件的自绘界面也能指定滚动位置。每次观察在原生层绑定调用方、进程、窗口和有效期；不同客户端互不覆盖控件引用与坐标映射。模型输入凭据六十秒过期且只能消费一次。

直接命令行 `biny cu scroll <ref> <方向>` 默认滚动一页，可用 `--pages` 指定页数，或用 `--amount` 显式选择滚轮刻度；同时给出时 `--pages` 优先。不带引用的方向形式默认一个刻度。`biny cu launch` 是 `launch_app` 的别名；`biny cu lens` 未指定模式时切换开关，未知模式在派发前拒绝。

按控件滚动会先尝试该控件及其滚动区域的无障碍动作；必要时以控件中心发送滚轮事件。引用失效或需要滚轮但无法确定落点时会拒绝输入，需重新观察或提供截图坐标。

控件行优先显示非空标题、描述、文字值或角色描述，保留完整文字；应用没有提供位置时不会显示坐标。文字等待也可匹配这些字段。原生观察的差异标志会计入控件增删、文字和状态变化；未变化数量按原位置统计。

无障碍窗口无法读取、控件分支读取失败或遍历达到时间、数量限制时，观察会提示相应原因；已经采集到的控件与可用截图仍会返回。无障碍树整体读取超时时也会保留可用截图。

系统明确拒绝的输入报告未执行；无障碍接口成功表示操作已接受，不代表业务结果已经达成。物理输入已投递后仍须根据返回的新观察核对业务结果，不自动重放。动作后观察失败时，可只读重新观察恢复；请求超时、取消或断线导致执行情况未知时，当前轮停止输入，用户恢复任务后先观察。用户主动暂停、接管和停用仍须由用户恢复。自动观察的临时截图在读取完成或失败后删除，迟到回包也会清理。

直接 CLI 可以先列窗口，再观察指定目标：

```bash
biny cu windows <pid> --json
biny cu get_app_state <pid> --window <window-id> --json
biny cu click --pixel 120 80 --pid <pid> --window <window-id> --json
```

PID 和窗口 ID 使用当前返回值。输入方式、控件可写性和窗口存在性按本次观察确认，不复用另一个窗口的引用。动作取消或结果不明时，先重新观察，不自动重复输入。

`cu windows` 也接受应用 bundle ID：先查找正在运行的应用，再读取该进程的窗口。应用未运行或查询途中退出时报告错误，不自动启动；只有应用存在且确实没有窗口时返回空列表。应用未提供窗口尺寸时显示“尺寸未知”。

无障碍窗口读取失败会返回权限或读取错误，不显示为“没有窗口”。应用明确不支持窗口属性时可使用系统窗口列表；两种来源都不可读取时报告 `window_list_unavailable`。启动预览保留读取失败原因，窗口查询恢复成功后才继续采集，不借用旧目标截图。

窗口列表按真实窗口 ID 合并无障碍与系统窗口信息，保留最小化窗口，不按列表顺序猜测对应关系。文本输出用 `*` 标记应用的聚焦窗口，并标注“已最小化”；JSON 保留可读取的 `focused`、`minimized` 和 `onscreen` 状态。无法取得窗口 ID 时显示 `0`，不能把它用于需要准确窗口号的操作。列表中的窗口不保证当前可截图；后台启动后的自动预览会跳过已知最小化或不在屏幕上的窗口，不主动恢复窗口。

直接 CLI 的物理点击、拖拽及像素右键需要显式传 `--window`。缺少精确窗口或窗口局部投递能力时拒绝，不再使用首个窗口或全局鼠标作为回退；`--window` 只指定目标，不隐式请求前台输入。

没有可用 AX 控件的自绘界面仍可按截图点击，并向已聚焦输入框输入文字。内置 `ComputerAction` 的 `type_text` 在 `auto`、`physical`、`unicode` 模式下不要求 `elementToken`；`ax` 模式才要求可写控件引用。所有模式仍要求同一准确窗口的有效 `captureId`。

后台是默认投递方式。后台物理点击和拖拽绑定准确窗口，使用窗口局部事件向目标进程投递，不走全局鼠标输入，也不主动隐藏、移动或还原用户鼠标。后台动作期间启用按目标进程限定的激活事件拦截；拦截不可用或无法确认窗口局部投递能力时拒绝动作，不回退到全局事件。点击后保留目标应用内部的新控件焦点，不把它还原到点击前。

后台键盘输入在每组按键和每段 Unicode 字符派发前，核对目标应用内部聚焦的窗口。焦点切换或无法确认时停止；这可能发生在部分文字已经输入之后，因此保留执行情况未知，不自动重放或转前台。没有可报告焦点的应用仍可能无法接受后台键盘输入，需要根据新观察选择可用的控件操作，或如实说明当前限制。

按键或滚轮事件无法创建时会明确报告失败，不返回已发送或已滚动；多字符输入中途创建事件失败时，前面的字符可能已经发送，应先观察结果，不自动重复整段输入。

后台 `press_key` 遇到应用没有聚焦窗口时，可查找匹配且启用的菜单快捷键；只有应用主窗口仍是观察中的目标窗口，才通过无障碍菜单执行。回执的 `via: "menu_ax_press"` 表示走了菜单路径；找不到匹配项或无法确认窗口时不会输入。菜单动作结果未知时须重新观察，不能重发快捷键。

`press_key` 接受 `cmd+s`、`ctrl+shift+t`、`F1`、`cmd+opt+esc` 和 `Super_L+d` 等组合，以及方向、翻页、删除和数字键盘键名。修饰键支持 `cmd` / `command` / `meta` / `super`、`ctrl` / `control`、`shift`、`opt` / `option` / `alt` 和 `fn`，也接受 `Control_L`、`Shift_R` 等左右键名；未知键名、修饰键或不完整组合在派发前拒绝，不会省略未识别部分后执行其他快捷键。

模型动作始终后台投递，不提供前台激活开关或投递模式参数。旧的 `delivery` 参数在派发前拒绝。后台派发失败时报告具体原因，不能激活目标窗口、临时切前台再恢复，或自动重放输入。人工命令行的显式窗口抬升及系统级按键入口仍由用户主动调用。

输入回执中的“效果待核对”表示调用已结束，但尚未确认业务结果，不作为调用失败或执行中断。系统保留原生警告，并返回动作后的截图与新观察凭据。模型直接核对输入框、结果页或播放条；信息足够时继续下一步，不额外观察，也不重放刚才的动作。没有可用画面时先重新观察。独立外部服务的动作回图不含新凭据，下一次输入前仍须重新观察。自绘应用的中文输入、真实后台焦点和不同 macOS 版本的拦截效果仍需人工核对，工具派发完成不代表目标已经接收。

独立 MCP 的动作回图失败时，工具保留动作回执，并在文字和结构化结果中报告截图失败原因；缺图不表示动作未执行。`sky_*` 刷新观察失败后尝试同一目标的纯截图，纯截图也失败时同样返回原因，下一步先重新观察，不能自动重复刚才的动作。

内置技能优先通过快捷键直接执行后台菜单命令，避免先展开菜单栏或弹出选择器找命令；展开菜单可能停留在用户屏幕上，并使目标应用暂时停止响应自动化查询。无法投递时报告具体原因，不用激活后恢复焦点的方式绕过。

## 连续动作、轻量观察与等待

`ComputerSequence` 在同一窗口连续执行一至五步，最长十五秒。首步可以定位或操作控件，后续只能向当前焦点输入文字或按键；需要查看结果才能决定的操作必须分开。控制器逐步检查授权并更新一次性观察凭据，中间只截图，最后按原观察模式返回画面与逐步回执。部分完成、拒绝、回图失败、暂停、接管或中断后不执行剩余步骤；部分步骤保留回执与可用截图，但不计入完成数量。已收到回执不等于业务目标已完成，不能重放整组操作。

观察默认包含截图与控件。`content: "image"` 跳过控件读取，只返回截图和新观察凭据；旧控件引用同时失效，后续可以使用当前截图坐标。它不改变系统权限要求，也不提供控件差异合并。

观察的 `waitFor` 可以等待控件标题、描述或文字值包含指定文本，例如 `{"text":"已保存","timeoutMs":5000}`。默认最多五秒，可设置为二百五十毫秒至十秒；每轮检查后至少间隔二百五十毫秒，匹配后立即返回当前观察。超时返回未匹配结果并撤销旧输入凭据，不自动重试或输入。文字出现只证明该条件成立，不证明整个任务完成；该功能不识别截图文字，因此不适用于没有控件文字的自绘界面，也不能与仅截图模式混用。

`select_text` 可使用 `matchText` 按文字选择范围，`prefix` 和 `suffix` 指定紧邻前后文来消除重复匹配。匹配缺失、存在歧义或正文在读取后发生变化时拒绝操作，不默认选第一处，也不修改正文。原有 `text` 参数仍表示替换选区；匹配与替换或位置参数不能混用。位置与长度使用系统选区的 UTF-16 单位。

内置工具、外部 MCP 和受控命令行共用 Desktop 控制器。外部 `get_app_state` 接受观察模式和等待条件，`sequence` 接受与内置连续动作相同的参数。未运行 Desktop 时，独立服务支持仅截图观察和文字选区；连续动作及条件等待会明确拒绝，不退回另一套控制器。

受控命令行提供 `observe`、`action`、`sequence` 和 `release`。前三个命令接收 JSON 参数，默认输出文字，`--json` 返回包含图像的完整回执。同一流程使用相同的 `--session`，完成后释放控制权；请求仍遵守 Desktop 的启用、应用审批、暂停和接管。下面的进程、窗口与观察凭据须换成当前实际结果：

```bash
biny computer observe '{"pid":42,"windowId":"900","content":"image"}' --session edit --json
biny computer sequence '{"pid":42,"windowId":"900","captureId":"当前观察凭据","actions":[{"action":"type_text","text":"测试"},{"action":"press_key","key":"Return"}]}' --session edit --json
biny computer release --session edit
```

## 按窗口镜像

```bash
biny cu pip open <window-id> --pid <pid> --json
biny cu pip open <window-id> --pid <pid> --on-minimize --json
biny cu pip list --json
biny cu pip close --all --json
```

普通镜像实时显示指定窗口；`--on-minimize` 先监听，在源窗口最小化时显示，不激活或恢复源窗口。列表返回会话状态与 `last_frame_age_ms`；没有收到帧时帧龄为 `null`，最后画面不能证明当前仍在更新。

关闭会话释放捕获和监听。内置 `ComputerMirror` 沿用应用审批。Desktop 将浏览器与电脑监督画面放在统一 PiP 中，可切换来源、关闭单项并返回聊天；预览默认开启，开关与窗口尺寸跨重启保存。

统一监督预览保持悬浮置顶；macOS 上在其他 Spaces 和全屏应用中也可见。打开时根据主窗口定位，并尽量避开聊天输入框；没有主窗口时使用鼠标所在屏幕的右下角。打开不激活，帧刷新不重新显示或提升窗口。可以拖动调整位置，主窗口移动时预览保持相对位置；关闭后重开会重新定位。画面上的控制在鼠标悬停或键盘聚焦时显示，异常状态始终可见。“关闭此项”收起画面，不等于停止正在执行的任务；同一来源的自动预览在关闭后不立即重开，能识别会话时按会话区分。连续十分钟没有新的自动活动后恢复，也可在设置中重新启用预览。暂停、人工接管和停止使用对应按钮。

多个预览来源各自更新；某个来源捕获缓慢时不阻塞其他来源。同一来源的捕获未结束前不会重复发起，超时或捕获容量用尽会显示状态，等在途请求结束后恢复更新。

由工作区聊天发起的电脑预览和原生镜像会保留所属项目与聊天，点击返回可定位该聊天，即使它不在侧栏当前加载的列表中。外部客户端未提供项目身份时，返回按钮仍可打开主窗口；能否定位聊天取决于可用的会话信息。

从内置浏览器预览返回时，会先回到关联项目和聊天，再展开该项目的内置浏览器。外部浏览器预览返回时不会打开内置浏览器。
当前来源的首张有效画面按宽高比调整窗口高度，以屏幕工作区高度的一半为上限，并受窗口最小尺寸约束；用户手动调整后，同一目标的后续帧不会再次改变尺寸，切换来源或目标窗口时重新适配。
电脑预览在画面内标记最近的操作落点；指针随画面缩放定位，约八秒无新操作后消失。只有落点属于当前目标窗口且位于画面范围内时才显示，不移动用户的鼠标。
自动预览闲置结束时，画面会淡出并收起；收起过程中有新活动时会继续显示。关闭当前项时立即停止该项预览，画面淡出后切到剩余来源；最后一项淡出结束后销毁窗口。关闭预览、暂停或停止等明确操作仍立即生效。

## 文本输入

```bash
biny cu type_text "ABC" --pid <pid> --input-method physical --json
```

`physical` 按当前键盘布局规划整个文本。布局无法表示的字符会在输入前拒绝，不静默改走 Unicode。`auto` 带控件引用时先尝试可写的 AX；明确不支持时可回退键盘，但须确认该控件或其内部元素已聚焦。AX 写入结果未知时停止，不再派发键盘输入。`ax` 需要有效的可写控件引用。以返回的实际路线和重新观察结果判断输入是否送达。

## 外部 MCP

stdio 入口：

```bash
biny computer mcp
```

在客户端配置命令 `biny` 和参数 `["computer", "mcp"]`。stdout 传输 MCP 协议。

本地 HTTP 入口：

```bash
biny computer mcp --http --port 0
```

输出包含 `url` 与 `tokenPath`。客户端从私有令牌文件读取值，以 `Authorization: Bearer <token>` 鉴权；服务监听本机回环地址。正常关闭时删除由本次服务创建的令牌文件，不能把强制终止当作清理已经完成。

独立 MCP 服务在工具参数的 schema 校验前限制数组元素与对象键的合计数量，最多 256 个，嵌套和未声明字段也计入；超限返回工具错误，不进入应用策略或执行动作。五步连续动作的全部声明字段仍在该预算内，文本长度不计入元素数，仍遵守各工具的文本限制。本地 HTTP 另保留 1 MiB 请求体上限，以及鉴权、Host 与 Origin 检查。

外部 MCP 保留独立连接。发现 Desktop 控制服务后，观察、启动、输入和镜像均交给同一个桌面控制器，遵守会话占用、暂停、接管和应用审批；已连接的 Desktop 中断时拒绝继续，不切换到独立输入。未运行 Desktop 时使用独立原生服务，仍检查全局开关、持久化审批和观察有效期；每次输入消费观察，下一次输入需要新的观察。多个窗口且没有唯一聚焦窗口时须显式选择窗口。断开会释放该连接拥有的桌面控制资源。

MCP 也提供 `sky_list_apps`、`sky_get_app_state` 及 `sky_` 前缀的点击、按键、输入、滚动、赋值、拖拽、次级动作和文本选择工具。观察结果包含截图 URL、编号控件和采集警告；后续操作只能使用该连接对同一应用最近一次观察中的编号。观察默认返回变化项和移除的编号，`disableDiff: true` 返回完整列表；应用有多个窗口时用 `window_id` 指定目标。输入后使用同一窗口的新观察：Desktop 复用动作回执中的观察，独立服务直接使用新观察的截图和凭据。仍是同一个无障碍元素的编号可以继续使用；消失的编号会报告并失效。刷新失败时保留动作回执，独立服务在控制和应用授权仍有效时尝试返回同一窗口的纯截图；纯截图不提供输入凭据，须重新观察，不能重发已派发的动作。编号不能跨连接或沿用过期捕获。截图 URL 包含图片数据，客户端应按截图处理；Biny 运行时将图片交给模型的图片通道，不写入会话文本。

观察不完整时，未在本次结果中出现的旧编号会标为不可用并停止接受输入；这不能证明对应控件已从应用中删除。动作后的新观察也会返回采集警告与不可用编号，供下一步判断。

`sky_perform_secondary_action` 可对编号控件指定无障碍动作名。普通 `perform_secondary_action` 和内置 `ComputerAction` 分别使用 `secondary_action` 和 `secondaryAction` 指定动作；省略时打开上下文菜单，只有菜单动作在明确不受支持时会尝试右键。普通 `perform_secondary_action` 使用坐标时默认按截图像素定位，设置 `coord_space: "screen"` 可使用屏幕坐标。

点击的 `auto` 在控件有位置时优先发送物理点击；没有位置时，单次左键尝试 AX 动作。显式 `ax` 只调用控件动作，双击和非左键必须使用物理事件。物理输入报错后不切换到 AX 重放。AX 点击动作、菜单与滚动只在无障碍接口明确报告不支持时尝试后续动作。赋值、文字输入和选区写入也区分明确不支持与结果未知。接口通信失败时系统会停止并要求重新观察，不自动重复输入。控件既不支持点击也没有位置时会明确报告未执行。

外部 `get_app_state` 的完整观察默认深度为 6，可显式设置 1–20；`depth: 0` 仅返回截图。它支持 `interactive_only`、`screenshot_max_width` 和 `auto_launch`，外部 `type_text` 支持 `input_method` 选择输入方式。已有的驼峰字段和 `content: "image"` 仍可使用，同一选项不能同时提供两种字段名。

完整观察的首个文字块是 JSON，`elements` 提供控件属性、可用于后续操作的 `ref` 和可用时的 `bounds`；结构化结果也包含这些控件。可读控件树以单独文字块返回，结果还包含适用的应用操作说明，截图以图片块返回。Biny 模型入口会保留控件与应用说明，并通过图片通道交付截图。

可用时，控件结果还包含子角色、当前值、选中状态、可用无障碍动作和子元素数量；数值以字符串呈现。控件没有名称时，会尝试读取关联的标题元素或标签值。可读树会显示与名称不同的值、选中状态和可用动作。筛选交互控件时，带无障碍动作的自定义角色也会保留；关闭筛选可查看容器的名称和位置。

读取控件时会临时启用应用的无障碍界面属性；同一应用的重叠读取结束后尝试恢复原有状态。若原状态不可读，则尝试按关闭状态恢复。

无障碍树读取超时会在观察结果中提示；如果截图可用，仍可依据截图使用坐标操作。过滤后没有交互控件时，可关闭过滤查看完整树。

截图采集、读取失败或图片超出限制时，结果会保留失败原因；这次观察不能用于输入，须重新观察。动作已投递而后续截图失败时，回执保留动作状态和失败原因，应先重新观察，不重复派发该动作。

外部 MCP 的 `select_text` 使用 `text` 查找并选中文本，不修改正文；`selection_type` 可选 `text`、`cursor_before` 或 `cursor_after`，`prefix` 和 `suffix` 用于区分重复文字。原先通过该入口的 `text` 替换选区的调用应改为选区定位后使用 `type_text`。内置 `ComputerAction` 的 `matchText` 对应文字查找，`selectionType` 选择相同的三种模式；其 `text` 仍表示替换当前选区。

外部 `drag` 可使用 `start_x`、`start_y`、`end_x`、`end_y` 指定起点和终点，也保留已有的 `x1`、`y1`、`x2`、`y2`；同一坐标不能同时提供两种写法。`button` 可选择左键、右键或中键，默认左键。

外部旧动词与 Desktop 工具共用动作校验和原生参数转换；旧名称及 `ref`、`click_count`、`coord_space`、`show_cursor` 别名保留。文本与字符串值最多 4,000 字符，控件引用最多 256 字符，按键最多 40 字符；点击与滚动的 x/y 必须成对，页数大于 0 且不超过 20，可以是小数。整页动作部分完成时回执会提示重新观察，不会自动重试；部分应用的滚动距离只能估算。文字匹配选区不能与替换文本或位置选区混用。未知字段和非法组合在派发前拒绝；模型参数公开相同的长度与范围约束，跨字段条件仍由执行入口校验。独立模式不支持文字等待与连续动作。


## 直接入口与日志

`biny cu` 是用户显式调用的直接原生入口，不经过产品应用审批与观察凭据校验。它受 macOS 权限与原生命令自身校验约束；Agent 不能用这个入口绕过已被拒绝的工具操作。

`get_app_state` 默认返回控件树与截图；`snap` 只读取控件树，不采集屏幕，也不接受截图保存选项。两者都将观察保存在守护进程的直接 CLI 范围，下一条独立命令可使用返回的控件引用。截图坐标操作前使用 `get_app_state` 获取画面。

`get_app_state` 截图成功时返回可读取的文件路径；`--out` 或 `--shot-out` 指定保存位置，相对路径以调用命令的目录为准，省略时生成独立临时文件。`--no-shot` 只读取控件，不改动指定文件；截图失败保留原因。输入命令的 `--no-cursor` 只隐藏本次动作提示，不改变后续命令。

`drag --button` 可选择 `left`、`right` 或 `middle`，默认左键；非法按钮和非有限坐标在输入前拒绝。`type_text --bundle <id>` 可按应用标识定位，输入方式接受 `--input-method` 或 `--input_method`，默认 `auto`。`set_value` 保留空字符串和纯空白文本，数字与 `true/false` 转换为对应类型。

`biny cu shot <bundle|pid> --window <window-id> --out <path> --json` 按指定应用和窗口保存图片；不传 `--window` 时保留该应用范围。应用标识先解析为进程，目标消失、窗口归属不符或参数无效时失败，不改为整屏截图。权限、捕获超时和空图片同样返回错误，不输出成功路径。

截图先写入独立临时文件，成功后才替换输出文件。失败或超时不会覆盖已有输出；超时后完成的捕获只清理自己的临时文件。

Agent 的 `Bash` 不作为桌面控制回退。macOS 下即使文件写入限制关闭，仍限制 AppleEvents、HID、辅助功能与 WindowServer 访问，并阻止连接已知原生 helper socket；直接调用 `biny cu` 或启动原生控制 MCP 也会被拒绝。普通文件命令和无关本地 IPC 不因此禁用。这不是任意外部服务的隔离保证：其他已授权远程服务仍按各自权限边界管理。

操作日志按需开启，只保存本地动作元数据。窗口附件快捷键见 [活动记录与 Appshots](ACTIVITY.md#appshots)，通用授权说明见 [工具与权限](PERMISSIONS.md)。
