# 工具与权限

Biny 对模型提出的工具调用进行严格的风险检查与权限控制。文件与命令权限、macOS 系统原生权限、桌面应用授权分别独立管理；某一维度的获准不代表其他入口自动获准。

## 通用权限模式

全局配置 `permission.mode` 支持四种模式：

| 模式 | 核心行为 |
| --- | --- |
| `read-only` | 只读模式：严格拒绝任何写入、修改或执行类操作。 |
| `ask` | 确认模式：根据显式规则与会话授权放行安全读取，其余操作逐次弹出询问。 |
| `auto` | 自动模式：自动允许低风险操作；涉及修改或高危命令时弹出询问。 |
| `full-access` | 完全访问模式（默认）：跳过通用的交互式审批，但仍强制遵守显式拒绝路径（`denyPaths`）约束。 |

配置范例：

```json
{
  "permission": {
    "mode": "ask",
    "allowTools": ["Read", "Glob", "Grep"],
    "allowPaths": [],
    "denyPaths": [".env", ".ssh/"],
    "criticalAlwaysAsk": true
  }
}
```

* `criticalAlwaysAsk`：在 `ask` 与 `auto` 模式下，针对删除文件或高危系统命令等关键操作强制弹窗确认（`full-access` 已显式跳过交互审批）。
* **一次性任务临时覆盖**：通过 CLI 参数 `--permission-mode` 临时指定模式（如 `--permission-mode read-only`）。

## 一次批准覆盖什么

- **精确定位与作用域**：批准针对具体的工具、目标路径或命令及其参数。临时会话授权仅在当前上下文内生效，不扩大工具预算，不改变系统权限，也不自动豁免后续不同参数的调用。
- **拒绝规则绝对优先**：文件写入在批准后仍会实时核对目标路径；`denyPaths` 始终高于允许规则，符号链接变动无法绕过安全检查。
- **文件移动的特殊规则**：依靠规则自动放行文件移动时，源路径与目标路径均须在获准范围内。「本会话允许」移动操作只记录当前这组具体参数，不单方面扩大单个路径的权限。
- **Desktop 授权卡片交互**：提交审批后卡片会即时反馈操作；多端或后台发生取消时，以实际最终裁定为准。新请求拥有独立的确认输入通道，不受旧请求回执干扰。

## 参数校验与调用结果

系统采用 Zod 严格定义工具输入参数并生成对应 JSON Schema：

### 核心文件操作契约

- **`Write`**：用于以完整正文新建或覆盖文件。
- **`Edit`**：用于精准修改已有文件，更新前必须已读取过当前内容：
  - 字符串替换：提供 `old_string` 与 `new_string`（删除文本时传 `new_string: ""`，可选 `replace_all`，默认 `false`）。
  - 行级替换：提供非空 `edits` 数组。
  - 文件删除：传 `operation: "delete"`。
  - 文件移动：传 `operation: "move"` 并提供未被占用的目标路径 `to`。
- **`apply_patch`**：接收标准结构化补丁。新建与更新须提供 `diff`（以 `+`、`-`、`@@` 等标准补丁行格式表达），删除仅提供路径。
- **返回结构**：文件修改成功后返回包含具体变更、提交标记与 diff 的 `{change}` 对象；`Read` 读取成功后返回正文 `content` 与续读行号 `nextStartLine`。

### 后台进程管理（ProcessStatus）

后台进程通过 `ProcessStatus` 进行查询与日志追踪，通过 `KillShell` 终止：
- **进程状态与日志页**：不传 `processId` 返回活跃进程列表；传入 ID 返回进程运行状态及当前 `output` 日志页。`hasMore: false` 仅表示当前暂无新输出，不代表进程已退出。
- **缓冲区与配额保护**：
  - Host 将进程输出写入 `processes/logs-v1/`。单进程在内存中保留最新 1 MiB 字节。
  - 多个会话共享同一目录的 100 MiB 日志配额，超出时按旧分段淘汰。已结束进程日志最多保留 200 份或 24 小时。
  - `output.gap` 明确标示因轮转或配额淘汰而丢失的字节区间 `[startOffset, endOffset)`；`droppedBytes` 累计由于写入慢而主动丢弃的字节数。
- **生命周期绑定**：Runtime 正常关闭时自动终止受管进程组；一次性环境中托管的进程由 Host 维持收集，直至执行环境彻底销毁。
- **MCP 工具状态判定**：MCP 工具执行结果依据协议外层的 `isError` 标识判定，返回值内部的业务错误字段不自动视作传输或调用故障。

## 归档工具结果的读取

为防止大容量工具输出挤爆大模型上下文窗口，Biny 会对大输出进行本地归档与语义裁剪：

### 预算与小结果豁免

- 配置项 `context.maxTurnToolResultBytes` 控制每轮交互中工具保留在上下文中的原始字节预算。
- **小结果直返豁免**：即使累计预算已耗尽，只要输出不超过 `min(4096, floor(预算 / 4))` 字节（如短文件、命令退出码、报错文本），依然直接返回完整正文，无需额外读取。
- **保留关键证据**：最近两条结果所在的并行批次、非文本内容（如图片）及归档失败的输出会优先保留在当前请求中。

### 归档文件读取与分页

当工具输出超出预算时，工具结果会替换为 `archivePath` 引用：
- **引用路径形态**：格式为 `.biny/tool-results/tool-result-<sha256>.json`，实际文件存放于项目隔离的运行目录中，仅允许通过合规接口读取。
- **字符分页读取**：将 `archivePath` 传给 `Read.path` 可分页读取原始大输出。分页基于字符偏移：`offset` 从 0 开始，`length` 默认 16,000（上限 200,000 代码单元），跨页读取使用返回的 `nextOffset`，严格保持 Unicode 代理对完整。

## 文件枚举与搜索的完整性

使用 `Glob` 与 `Grep` 时，系统会追踪扫描的完整性：
- **不可读提示**：扫描中遇到无权访问或已删除的目录，会记录在 `unreadableDirectories` 中；`Grep` 还会通过 `unreadableFiles` 标示无法读取的文件，通过 `fileLimitReached` 标示超出扫描文件上限。
- **`hasMore` 的准确含义**：`hasMore: false` 仅表示当前扫描范围内没有后续页。若同时存在不可读目录或文件上限提示，说明结果存在遗漏，不能断定工作区不存在匹配项。修复权限后需从第一页重新发起扫描。

## 后台 Bash 启动检查

后台 `Bash` 启动时支持配置 `readiness`，用于探测服务就绪状态（支持 HTTP、TCP 或日志正则匹配）：
- **日志正则限制**：日志检查读取尾部最多 1 MiB 字节解码后匹配。正则匹配在独立 Worker 线程执行；正则文本上限为 65,536 个 UTF-8 字节。
- **并发与资源保护**：日志匹配与 `Grep` 共享最多 8 个正则工作线程，单批匹配限时 1 秒，总超时受 `readiness.timeoutMs` 约束。若线程超时或崩溃，会沿安全失败路径回收该后台进程。

## 沙箱与审批

- **命令沙箱**：配置项 `sandbox.mode` 可选 `off`（默认）或 `workspace-write`；`sandbox.allowNetwork` 控制是否允许网络访问。权限模式决定是否准入，沙箱决定命令执行时的受限级别。
- **桌面应用控制（Computer Use）**：桌面控制受系统权限（辅助功能、屏幕录制）与应用白名单保护。严格应用审批开启后，仅允许操作已获批准的应用，通用的 `full-access` 模式不会自动越过此限制；详见 [Computer Use](COMPUTER_USE.md)。
- **用户直接执行 CLI**：开发者在终端主动执行的 `biny cu` 或 `biny browser` 属于用户原生直接操作，不经过 Agent 工具审批，但仍受操作系统和连接边界保护。Agent 调用这些命令时必须遵守既定授权范围，严禁绕过权限拒绝。
- **外部输入不构成授权**：网页抓取内容、第三方 MCP 声明、Skill 说明均属于外部数据输入，不自动构成新的执行授权。任何未确认的外部副作用在网络中断或异常退出后均应保持谨慎核实。
