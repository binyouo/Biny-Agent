# 工具与权限

Biny 对模型提出的工具调用检查操作、目标、风险与当前授权。文件和命令权限、macOS 系统权限、桌面应用授权分别管理；一个入口获准不能自动证明其他入口获准。

## 通用权限模式

全局配置的 `permission.mode` 支持：

| 模式 | 行为 |
| --- | --- |
| `read-only` | 拒绝非读取操作。 |
| `ask` | 根据显式规则、会话授权与低风险读取判断，其余请求询问。 |
| `auto` | 在已有规则之外，自动允许低风险操作；其余请求询问。 |
| `full-access` | 跳过通用交互审批，仍执行显式拒绝路径检查。 |

当前默认模式是 `full-access`。`ask` 不表示每一次读取都弹出确认，`auto` 也不表示所有操作都自动允许。

下面是合入全局配置的示例片段：

```json
{
  "permission": {
    "mode": "ask",
    "allowTools": ["Read", "Glob", "Grep"],
    "allowPaths": [],
    "denyPaths": [".env", ".ssh/"],
    "criticalAlwaysAsk": true
  }
}
```

在 `ask` 与 `auto` 中，关键风险操作会按 `criticalAlwaysAsk` 请求确认；`full-access` 已明确跳过这层交互审批。

一次性任务可以临时覆盖模式：

```bash
biny run "检查项目结构" --permission-mode read-only --json
```

## 一次批准覆盖什么

批准针对实际工具、路径或命令及其参数。临时会话授权只在相应范围内生效；它不扩大工具预算、不改变系统权限，也不让后续不同目标自动通过。

文件写入在批准后继续核对目标路径和文件状态。拒绝路径优先于一般允许规则；软链或目标变化不能用旧批准绕过检查。

Desktop 的授权卡片可以先显示本次提交的选择；收到同一请求的实际审批结果后，以该结果和说明为准，即使提交回执仍在等待。任务取消或其他客户端已作出决定时，不会继续把本地选择显示成实际授权结果。新请求的确认输入独立，旧提交的迟到回执不会关闭新请求。

## 参数校验与调用结果

`Read`、`Write`、`Edit`、`ProcessStatus` 及结构化 `apply_patch` 的参数由 Zod 定义，同时生成发给模型的 JSON Schema。`Edit` 每次只处理一个源文件：字符串更新必须提供 `old_string` 和 `new_string`，删除匹配文本时显式传 `new_string: ""`；Hashline 更新提供非空 `edits`；删除整文件用 `operation: "delete"`；移动用 `operation: "move"` 并提供 `to`，目标不得已存在。字符串替换允许省略 `operation`（默认更新）和 `replace_all`（默认 false）。缺少参数或分支带有无关参数，在权限确认和执行前拒绝。

`Write` 使用完整内容创建或覆盖文件，`Edit` 更新要求先读取当前内容。结构化 `apply_patch` 每次接收一个文件操作：创建和更新必须提供 `diff`，删除只提供路径。创建 diff 的内容行以 `+` 开头；更新使用 `@@` 段落标记及空格、`-`、`+` 行前缀，不添加文件头或整份补丁包装。文件变更工具返回 `{change}`，包含实际操作、路径、提交标记和 diff；`Read` 返回对象，正文位于 `content`，普通文件用返回的 `nextStartLine` 续读。

后台进程通过 `ProcessStatus` 查询：省略 `processId` 返回进程列表，指定 ID 返回 `process` 状态及 `output` 日志页。使用 `output.nextOffset` 按字节续读；`hasMore: false` 只表示当前没有更多日志，不代表进程已退出。停止进程使用 `KillShell`。新工具目录及权限规则只使用 `ProcessStatus`，不提供旧名称别名或自动转换；已有会话记录保持原样。

MCP 工具已返回回执时，执行失败依据协议外层的 `isError` 判定。查询得到的 `approved: false`、业务 `status: "failed"` 或业务 `error` 字段仍可属于成功查询；它们不会自动变成调用失败。权限拒绝、传输中断及副作用未知继续按各自执行状态处理，未知操作不会自动重试。

## 归档工具结果的读取

归档把大输出保存在本地，并向模型提供有界正文或引用，避免每次请求携带全部历史输出。`context.maxTurnToolResultBytes` 控制回合行内输出及请求中保留的工具正文预算；累计预算耗尽后，不超过 `min(4096, floor(预算 / 4))` 字节的小结果仍直接返回，让短文件、退出码与错误反馈无需额外读取。

请求发送前，较旧的工具正文可转换为可回查引用。最近两条结果所在的完整并行批次、图片等非文本内容，以及无法成功归档的证据会保留，所以该预算不是整个请求的硬上限；模型窗口检查和上下文压缩仍独立执行。此投影不改写原始会话事实。

工具结果超过上下文或持久化预算时，会返回 `archivePath`。将该引用传给 `Read.path` 可以取回原始输出；归档采用字符分页，`offset` 从 0 开始，`length` 默认 16,000、最大 200,000 个 UTF-16 代码单元，后续页使用返回的 `nextOffset`。分页保留完整的 Unicode 代理对，因此 `length: 1` 遇到这类字符时会返回两个代码单元。普通文件和附件继续用 `startLine`、`lineCount` 按行读取。

归档引用只接受 `.biny/tool-results/tool-result-<sha256>.json` 形态，实际文件位于项目隔离的运行目录；这不开放其他运行数据路径。读取仍经过权限与文件安全校验，子 Agent 不能通过此入口读取父会话归档。历史归档格式保持可读。

## 文件枚举与搜索的完整性

`Glob` 与 `Grep` 保留可读取的结果；扫描时无法读取或已经消失的目录记录在 `unreadableDirectories`，路径相对于工作区，`.` 表示工作区根目录。`Grep` 另外用 `unreadableFiles` 标记读取失败的文件，用 `fileLimitReached` 标记候选文件超过扫描上限。

`hasMore` 只表示发现的结果还有下一页。即使它为 `false`，上述跳过或上限提示仍表示结果不完整，不能据此认定工作区中没有其他匹配。恢复目录访问后应从第一页重新扫描；原有游标不会补回先前跳过的内容。主动忽略的路径及与指定 `path` 无关的目录不列入跳过提示；无法读取的祖先目录仍会报告。`Glob` 续页不会重扫完全位于 `cursor` 之前的子树，因此也不会在当前页重复报告那些子树的读取失败；当前页提示只覆盖仍可能包含游标后文件的扫描范围。先前页的读取失败并未因此消除，恢复访问后仍须从第一页重新扫描。

解析新 `Grep` 输出的调用方应使用 `unreadableFiles`；不再提供 `skippedFiles` 字段或别名。已保存的会话和归档不会改写，旧归档的预览或 `Read` 返回文本仍可能因敏感文本过滤而丢失旧字段名称。需要完整的具名警告时，应重新搜索生成新结果。

## 后台 Bash 启动检查

后台 `Bash` 的 `readiness` 可检查 HTTP、TCP 或日志。日志检查读取末尾最多 1 MiB 原始字节，按 UTF-8 解码后作为完整字符串匹配，保留跨行和零宽匹配。`regex: true` 使用独立工作线程，轮询复用同一实例；普通文本匹配、HTTP 和 TCP 不创建正则线程。

日志正则模式现在最多为 65,536 个 UTF-8 字节，工具参数校验和进程启动前校验均会拒绝超限模式；这是新增的输入限制。该上限不是字符数或 JSON Schema 的 `maxLength`，多字节字符同样按 UTF-8 字节计算。普通文本模式不受这个正则上限限制，正则语法仍在启动进程前检查。

日志匹配与 `Grep` 共用最多 8 个正则工作线程和既有资源保护：启动最多 5 秒、每批匹配最多 1 秒。日志检查为解码后的完整尾部保留最多 3 MiB 的批量字节预算；`Grep` 默认的 1,114,112 字节批量上限不变。线程退出后才释放配额。资源耗尽、线程故障或线程自身保护超时作为启动检查执行失败，沿已有失败路径回收后台进程。

总 `readiness.timeoutMs` 同时约束正则启动和匹配。总期限到达返回 `timed_out`，后台进程仍归 Runtime 管理；外部取消则走已有启动取消与回收路径。匹配结束后仍等待线程清理，并复核取消、进程退出和停止请求，避免返回过期的就绪结果。这些边界不承诺文件读取或线程终止获得严格的总墙钟时限。

## 沙箱与审批

`sandbox.mode` 可选择 `off` 或 `workspace-write`，`sandbox.allowNetwork` 控制所配置沙箱中的网络策略。当前缺省为 `off`、`allowNetwork: true`。

权限模式决定是否准入，沙箱约束实际命令执行。启用其中一项不表示另一项已经开启；也不能把插件的进程内代码加载描述成命令沙箱的一部分。

## 桌面应用

Computer Use 另外要求系统能力与产品开关。严格应用审批开启后，只允许已批准的应用，通用工具的自动允许和 `full-access` 不覆盖这个条件。

首次发现、批准与撤销记录保存在全局配置。关闭产品入口或撤销应用授权影响后续控制；已经派发给系统的输入不能撤回。具体操作见 [Computer Use](COMPUTER_USE.md)。

## 用户直接执行的 CLI

本机用户执行命令与模型工具审批不同。`biny cu` 是直接原生入口，不经过产品应用审批和观察凭据校验；`biny browser` 的直接命令也不经过模型工具审批。它们仍受各自系统、连接和文件边界约束。

Agent 使用这些 CLI 时仍须遵守用户授予的任务范围，不能改用命令绕过被拒绝的模型工具操作。

## 外部内容与未知结果

网页、工具返回、MCP 说明和 Skill 文本都是内容来源，不授予新的操作权限。读取页面不等于获准发送消息，连接服务不等于获准支付或删除资料。

取消、超时或断线后，已派发的操作可能已经发生。状态无法确认时保留未知结果，检查实际目标后再决定恢复；重新连接不能充当写操作重试。
