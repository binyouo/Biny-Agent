# 评测

Biny 使用确定性检查验证实现行为，使用独立模型评测观察任务质量。二者的输入、成本和结果含义不同，界面体验还需要人工确认。

## 实现检查

在仓库根目录使用：

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

`pnpm test` 包含标准测试与端到端测试。端到端入口会先构建 CLI；`pnpm build` 同时构建 CLI 与 Desktop。聚焦某个行为时，可先运行覆盖该行为的具体测试文件。

这些测试使用本地文件、数据库、子进程和协议替身覆盖行为。它们通过不代表真实服务商可用，也不证明模型在任意项目中能正确完成任务。

## 内置模型评测

```bash
biny eval run --label baseline --out baseline.json
biny eval compare baseline.json candidate.json
```

评测运行使用实际模型配置，会发起模型请求并产生相应用量。`--task` 可选择指定任务；比较要求两份真实报告，不用预期结果代替。

执行前固定模型、端点协议、思考配置、步数与费用预算、工作区、记忆策略及 verifier。隔离会话与记忆，避免前次运行内容影响新结果。随机性较大的任务需要重复运行，并保留每次原始输出与状态。

## Terminal-Bench

仓库提供 [Harbor 接入说明](../scripts/evals/harbor/README.md) 与相应 adapter。Harbor 管理任务环境，官方 verifier 检查实际产物；Agent 回答文本不参与最终通过判定。

使用时需具备 Harbor、Docker 和对应模型凭据。服务商密钥留在环境或私有文件中，报告只保留脱敏配置。任务环境安装、网络、超时和 verifier 失败与模型未完成任务分别记录。

历史例子见 [DeepSeek V4.1 Flash 评测报告](eval/terminal-bench-2.1-deepseek-v4.1-flash-biny.md)。该报告记录指定日期和配置下的运行，不是当前版本自动继承的成绩。

## 成绩口径

| 结果 | 能说明什么 |
| --- | --- |
| Pass@1 | 每题首次符合口径的有效运行结果。 |
| 重跑通过 | 后续尝试达到 verifier 要求，需单独标注次数。 |
| 多轮并集 | 至少一次通过的覆盖情况，不能当成单轮 Pass@1。 |
| 环境或 verifier 失败 | 该次运行缺少有效任务判定，不能伪装成测试通过。 |
| 模型报告完成 | 模型的语义判断，仍需外部证据确认。 |

比较策略时保持其他变量一致，按需要做消融。一次 API 成功、一个例子或更高的多轮并集不能单独证明代码改动提升了质量。

## 结果交付

报告写明运行配置、任务版本、预算、原始产物位置、退出状态、verifier 证据与未验证范围。聚焦测试、完整测试、构建、真实模型请求和人工界面验收分别报告。

Desktop、TUI 和浏览器交互通过人工步骤检查。非界面协议测试与构建可以作为实现证据，不能替代实际窗口、系统权限和输入法体验。
