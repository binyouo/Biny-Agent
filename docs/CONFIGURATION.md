# 模型与配置

Biny 将服务商连接与模型选择分开管理。一个服务商连接可以提供多个模型；会话使用模型别名，别名再指向服务商和实际模型 ID。

## 配置存放在哪里

| 路径 | 用途 |
| --- | --- |
| `~/.config/biny/config.json` | 全局模型、权限和扩展设置。 |
| `<项目>/.biny/settings.json` | 当前项目的模型及部分运行参数覆盖。 |
| `~/.config/biny/models-store.json` | 模型目录缓存。 |
| `~/.biny/agent/` | 按项目分区保存会话和运行状态。 |

`BINY_AGENT_DIR` 会同时重定向全局配置目录和运行数据根目录，适合隔离环境。设置后需在使用同一数据的 Desktop、CLI 和 Host 进程中保持一致。

项目覆盖只接受已支持的运行字段，例如 `defaultModel`、`thinking`、`agent`、`context`、`sandbox`、`checkpoints` 和 `diagnostics`。服务商连接与凭据在全局配置中管理；项目文件中的模型别名必须已存在于全局 `models`。

## 第一次配置

在源码仓库执行：

```bash
pnpm dev -- init
pnpm desktop:dev
```

`init` 创建缺失的全局配置与运行目录，保留已有配置。在 Desktop 的模型设置中添加服务商，填写连接信息，再获取或手动添加模型。地址与协议位于默认收起的“API 端点”中；模型列表下方可展开“手动添加”，搜索后的全选只作用于当前结果。连接信息和模型开关自动保存；模型选项对话框需要点击保存。删除服务商会先弹出确认，取消不会更改配置。保存失败会显示原因并保留输入供重试，离开供应商面板或关闭设置前会提交待保存的密钥和地址。

新建连接即使没有模型也可以启用；此时面板会提示获取或手动添加模型。模型目录获取成功只说明已获取列表；“测试连接”会对选定模型发送实际请求，第一次对话也会检查凭据和模型请求。

供应商总开关独立于模型选择。停用会保留连接、密钥和模型偏好，阻止该供应商的新模型与 embedding 请求；重新启用恢复原来的选择。配置字段 `providers.<别名>.enabled` 省略或为 `true` 表示启用，`false` 表示停用。单个模型开关控制它是否显示在模型选择器中，不删除模型配置。列表的状态圆点表示启用与本地凭据状态，不代表远端连接健康。

## 使用环境变量提供凭据

以下是需要合入已有全局配置的字段片段，使用仓库默认的 DeepSeek 模型配置作为例子：

```json
{
  "defaultModel": "deepseek-v4-flash",
  "providers": {
    "deepseek": {
      "type": "deepseek",
      "baseUrl": "https://api.deepseek.com",
      "apiKeyEnv": "DEEPSEEK_API_KEY"
    }
  },
  "models": {
    "deepseek-v4-flash": {
      "provider": "deepseek",
      "model": "deepseek-v4-flash"
    }
  }
}
```

把自己的密钥通过本地环境管理方式设置为 `DEEPSEEK_API_KEY`。环境变量必须对发起模型请求的进程可见；从 Dock 打开的 Desktop 不会自动继承另一个终端里临时设置的变量。

这三个名称分别是：

- `deepseek`：服务商配置别名。
- `deepseek-v4-flash`：Biny 选择的模型别名。
- `models.<别名>.model`：发给服务商的模型 ID。

自定义网关应使用它实际支持的 Provider 类型、端点、协议和模型 ID。修改显示名称不会改变请求协议。

## 凭据保存

当前配置保存链路将凭据正文与普通设置分开保存。macOS 命令行使用 Keychain；Desktop 及其独立 Electron Host 使用 Desktop 凭据存储。没有持久凭据存储的平台使用配置声明的环境变量。

同一个配置引用在另一个入口中是否可用，取决于对应凭据存储是否有该值。跨 Desktop 与终端使用时，若提示缺少凭据，检查入口使用的存储或共同可见的环境变量。不要通过提交配置文件、打印令牌或复制会话日志解决凭据问题。

API Key 默认打码显示，点击右侧图标可查看；输入新值后自动保存。输入框清空只取消当前编辑，不删除已保存密钥。账户登录凭据由登录入口管理。

旧配置可能仍有 `apiKey`。这些文件属于敏感本地数据；公开示例使用 `apiKeyEnv`，不放真实密钥。

## 模型切换与辅助请求

运行中保存新的模型或思考设置，后续根回合采用新选择。当前已开始的回合保持准入时的选择；保存成功不表示当前请求已经换了模型。

同一 Desktop 主窗口中的模型与思考选择按选择顺序保存，切换会话不会重置待完成的顺序。切换项目后，已排队的选择仍使用选择时的项目上下文；共享默认模型与项目覆盖的优先级不变。

`toolModel` 用于共享辅助模型选择。显式指定时应填写已配置的模型别名；省略时按可用配置自动选择。压缩、记忆处理和活动分析可能额外发起模型请求，其用量与聊天主请求分别记录。

### 聊天输出额度与截断

`chat.maxOutputTokens`（设置中的“最大令牌数”）是每次模型请求的输出上限，不是整轮对话的总额度。默认留空，优先使用当前模型的显式配置，未覆盖时跟随其服务商目录与已知模型元数据；没有声明额度时不发送这一参数，由服务商决定。模型 profile 的输出设置优先于模型别名配置，别名配置优先于自动元数据。自动模式不另设统一的输出额度，切换模型后使用该模型自己的额度。

填写“最大令牌数”会全局覆盖模型额度，切换模型也会沿用；在「设置 → 聊天 → 高级设置」点击“恢复自动”并保存可清除该覆盖，温度等其他聊天设置不变。输出包括正文和工具参数，部分模型的思考也占用这份额度。因此启用高强度思考时，即使可见正文很短，也可能触发长度上限。目录额度只是服务商声明，不保证当前账户可用，也不会让服务商忽略自身限制。

模型返回 `length` 时，Biny 保留已完成步骤与部分回复，将回合标为可继续的未完成状态。提示显示本次请求的有效上限与可用的输出、思考用量，缺失数字不推测。可提高“最大令牌数”，或降低思考强度后继续；提高上限仍受服务商限制，也可能增加耗时与用量。截断的工具调用不会执行，已完成工具不会自动重放。上下文压缩主要减少输入，不能替代输出额度调整。

模型目录中的能力、上下文窗口和价格是元数据。目录刷新失败不证明聊天连接失败，目录存在也不证明账户额度或远端请求可用。

目录刷新遇到 HTTP 错误时显示状态、请求地址和最多 8,192 个字符的诊断前缀。尾部读取失败不会抹掉已取得的诊断，错误响应不会替换上次有效目录。

## 本地配置检查

在目标项目目录运行 `biny doctor`，检查全局配置与当前项目 `.biny/settings.json` 合并后的配置。文件读取、JSON、字段类型或模型别名校验失败时，命令显示配置来源和检查方向并以非零状态退出，不回显配置值或解析器的原始 JSON 片段；通过后显示 `configuration: valid`。尚未配置时按运行入口使用默认值，不要求先运行 `init`。项目根目录的旧 `config.json` 仍只提示存在，不会加载。

此检查不会发起模型请求，也不验证 API 密钥、登录状态或远端服务可用性。有效配置中仍有内联 `apiKey` 时会显示迁移提醒，不输出密钥值。

## 排查

| 现象 | 检查 |
| --- | --- |
| 找不到模型别名 | `defaultModel` 与项目覆盖是否引用全局 `models` 中的键。 |
| 缺少密钥或登录过期 | 当前入口的凭据存储、环境变量和服务商登录状态。 |
| 连接存在但请求失败 | 端点协议、实际模型 ID、服务商额度和返回错误。 |
| 修改后当前回合没变化 | 新选择从后续根回合生效。 |
| 全局选择被项目覆盖 | 当前项目 `.biny/settings.json` 的 `defaultModel`。 |

配置结构以 [schema.ts](../src/config/schema.ts) 和 [项目设置](../src/config/projectSettings.ts) 为准；路径解析见 [paths.ts](../src/config/paths.ts)。权限模式另见 [工具与权限](PERMISSIONS.md)。

## 子代理执行预算与权限

子代理默认持续执行到正常交回、取消或故障，不设置固定模型步数和任务总时限。并发、排队容量、单次模型请求与前台命令超时仍各自生效；子代理结束后释放运行资源，执行记录保留供查询。

可在全局配置的 `extensions.subagent` 中显式设置 `maxSteps`（1–100000 轮模型调用）、`timeoutMs`（1000–2147483647 毫秒，包含排队时间）或 `maxCostUsd`。费用阈值要求模型价格信息完整。`inactivityTimeoutMs` 默认 300000 毫秒，每次模型输出或工具进度都会重新计时；只有持续无活动才停止，并显示“无响应”。删除 `maxSteps` 或 `timeoutMs` 字段即取消对应限制；旧配置中已保存的数值继续生效，不会自动当作默认值忽略。费用在请求结束后结算，阈值不能保证最后一次请求绝不超额。

子代理只能使用任务获准的工具集合，并逐次通过父会话的权限管理器判定；只读任务不暴露写入和命令工具。工作区任务可运行所需的有限命令，包括执行刚编写的程序，不再限定为几个测试或构建命令名称。显式拒绝路径传入同一命令沙箱；系统无法落实限制时拒绝启动。子代理仍不提供后台进程、再次委派或任意会话消息能力。

权限拒绝或需要批准时，子代理保存失败调用并停止，向父代理交回精简的操作与原因，不会自动批准或换命令重试。内嵌执行卡片保持只读，分别显示“权限受阻”或“待父代理处理授权”；已结束的任务不会因父代理后续完成工作而改写为成功。父代理可在自己的正常权限流程处理该操作，或在获得必要授权后派发新任务。
