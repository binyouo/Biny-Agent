# 模型与配置

当前配置文件使用 `biny-config` v2，项目设置使用 `biny-project-settings` v2。历史格式与旧目录不自动升级或搬移；不支持的版本会报错，来源文件保持原样。凭据安全存储是当前写入契约，内联凭据的持久化处理见下文。

Biny 将服务商连接与模型选择分开管理。一个服务商连接可以提供多个模型；会话使用模型别名，别名再指向服务商和实际模型 ID。

## 配置存放在哪里

| 路径 | 用途 |
| --- | --- |
| `~/.config/biny/config.json` | 全局模型、权限和扩展设置。 |
| `<项目>/.biny/settings.json` | 当前项目的模型及部分运行参数覆盖。 |
| `~/.config/biny/models-store.json` | 模型目录缓存。 |
| `~/.biny/agent/` | 按项目分区保存会话和运行状态。 |

`BINY_AGENT_DIR` 会同时重定向全局配置目录和运行数据根目录，适合隔离环境。设置后需在使用同一数据的 Desktop、CLI 和 Host 进程中保持一致。

项目覆盖只接受已支持的运行字段，例如 `defaultModel`、`thinking`、`agent`、`context`、`sandbox`、`checkpoints` 和 `diagnostics`。服务商连接与凭据在全局配置中管理；项目文件中的模型别名必须已存在于全局 `models`。

### 工作区指令预算

`context.instructionsMaxBytes` 限制全局与项目各级指令正文的累计 UTF-8 字节数，不包含后续装配的路径和提示词标签。截断不会拆开有效 Unicode 代理对；剩余预算大于 12 字节时包含换行及 `[truncated]` 标记，否则只保留能容纳的正文前缀。边界无法容纳的字符不会变成替换字符，未用字节仍可供后续目录的指令使用。读取和计数由 [WorkspaceContext](../src/agent/context/WorkspaceContext.ts) 负责，回归入口为 `tests/workspace-instruction-unicode-budget.test.ts`。

## 第一次配置

命令行可用 `biny config get/set` 读取和修改全局配置，`biny provider list/add/remove` 管理连接，`biny model list/set` 查询模型并选择全局默认。它们复用配置存储和模型选择校验，不改写项目覆盖；Desktop 加密凭据由正在运行的 Desktop 解密。具体示例、执行条件与设置生效时机见 [CLI 使用指南](CLI_USAGE.md#配置provider-与模型)。

在源码仓库执行：

```bash
pnpm dev -- init
pnpm desktop:dev
```

`init` 创建缺失的全局配置与运行目录，保留已有配置。在 Desktop 的模型设置中添加服务商，填写连接信息，再获取或手动添加模型。地址与协议位于默认收起的“API 端点”中；模型列表下方可展开“手动添加”，搜索后的全选只作用于当前结果。连接信息和模型开关自动保存；模型选项对话框需要点击保存。删除服务商会先弹出确认，取消不会更改配置。保存失败会显示原因并保留输入供重试，离开供应商面板或关闭设置前会提交待保存的密钥和地址。

自定义服务商创建和模型选项保存期间，当前对话框的字段、恢复推荐配置与图标选择暂时禁用，避免成功关闭时丢弃继续输入的内容；保存失败后保留原输入并恢复编辑。

新建连接即使没有模型也可以启用；此时面板会提示获取或手动添加模型。模型目录获取成功只说明已获取列表；“测试连接”会对选定模型发送实际请求，第一次对话也会检查凭据和模型请求。

供应商总开关独立于模型选择。停用会保留连接、密钥和模型偏好，阻止该供应商的新模型与 embedding 请求；重新启用恢复原来的选择。配置字段 `providers.<别名>.enabled` 省略或为 `true` 表示启用，`false` 表示停用。单个模型开关控制它是否显示在模型选择器中，不删除模型配置。开关不会改变模型在列表中的位置；保存期间列表暂时禁用模型修改，完成后可以继续操作，失败时可重试。列表的状态圆点表示启用与本地凭据状态，不代表远端连接健康。更换或清除服务商图标只更新展示偏好。

## 发送前脱敏

在 Desktop「设置 → 隐私脱敏」开启并保存，或执行 `biny config set redaction.enabled true`；默认关闭。工作流程、回复还原、缓存与重启边界见 [隐私脱敏](PRIVACY.md)。

## 使用环境变量提供凭据

以下是需要合入已有全局配置的字段片段，使用仓库默认的 DeepSeek 模型配置作为例子：

```json
{
  "defaultModel": "deepseek-v4-flash",
  "providers": {
    "deepseek": {
      "type": "deepseek",
      "baseUrl": "https://api.deepseek.com",
      "apiKeyEnv": "DEEPSEEK_API_KEY"
    }
  },
  "models": {
    "deepseek-v4-flash": {
      "provider": "deepseek",
      "model": "deepseek-v4-flash"
    }
  }
}
```

内置服务商的生图命令在未设置 `apiKeyEnv` 时沿用服务商默认变量名（如 `GEMINI_API_KEY`）；显式指定的变量缺失或为空时不会改读默认变量。

把自己的密钥通过本地环境管理方式设置为 `DEEPSEEK_API_KEY`。环境变量必须对发起模型请求的进程可见；从 Dock 打开的 Desktop 不会自动继承另一个终端里临时设置的变量。

这三个名称分别是：

- `deepseek`：服务商配置别名。
- `deepseek-v4-flash`：Biny 选择的模型别名。
- `models.<别名>.model`：发给服务商的模型 ID。

自定义网关应使用它实际支持的 Provider 类型、端点、协议和模型 ID。修改显示名称不会改变请求协议。

## 凭据保存

当前配置保存链路将凭据正文与普通设置分开保存。macOS 命令行使用 Keychain；Desktop 及其独立 Electron Host 使用 Desktop 凭据存储。没有持久凭据存储的平台使用配置声明的环境变量。

Desktop 启动时登记自身位置，终端冷启动发现桌面加密凭据后会复用同一安装的 Electron Host。Windows 安装或移动 Desktop 后先打开一次应用；若提示登记位置失效，重新打开当前安装即可更新。登记文件只保存启动位置，不保存密钥。

同一个配置引用在另一个入口中是否可用，取决于对应凭据存储是否有该值。跨 Desktop 与终端使用时，若提示缺少凭据，检查入口使用的存储或共同可见的环境变量。不要通过提交配置文件、打印令牌或复制会话日志解决凭据问题。

API Key 默认打码显示，点击右侧图标可查看；输入新值后自动保存。输入框清空只取消当前编辑，不删除已保存密钥。账户登录凭据由登录入口管理。

旧配置可能仍有 `apiKey` 或 OAuth `refreshToken`。CLI 与 Desktop 读取时使用各自的持久凭据后端执行事务迁移：确认凭据写入后才移除配置内联值，重复读取不重复迁移。后端不可用或迁移失败时保留来源并报错；没有持久后端的平台须改用 `apiKeyEnv`。迁移不在 Keychain 与 Desktop 存储之间复制凭据，也不新建含明文密钥的备份。旧文件仍属于敏感本地数据；公开示例不放真实密钥。

配置保存使用同一套锁、版本冲突校验与凭据补偿事务。项目覆盖仍优先生效。跨设置段的延迟事务只接受当前项目的有效配置；如需修改被项目设置遮住的全局字段，须使用全局配置视图，避免回滚时无法还原全局旧值。

## Telegram 渠道

`biny telegram run` 在前台连接 Telegram Bot API，并把主人发来的私聊映射到当前工作区的独立 Session。先通过本地环境管理方式设置 `BINY_TELEGRAM_BOT_TOKEN` 和自己的数字 Telegram 用户 ID `BINY_TELEGRAM_OWNER_ID`，再私聊 bot 并运行命令。Heartbeat 通知和 Agent 的 `dm-owner` 命令由 Runtime Host 通过本地连接交给正在运行的 Telegram 桥接进程投递；Host 不保存 Bot Token。要接收这类主动消息，需保持 `biny telegram run` 运行。Bot Token 不写入 Biny 配置、会话或渠道状态文件。

群聊需要将群组或超级群的数字 ID 加入 `BINY_TELEGRAM_GROUP_IDS`，多个 ID 用逗号分隔。白名单群里的成员明确提及 Biny 或回复 Biny 自己发的消息时可以触发 Agent；主人消息保留已配置的工具和 Skill，其他成员的回合禁用工具和 Skill，只能回应群内请求，不能执行操作或披露私密信息。群巡查读取最近消息摘要，至少静默 5 分钟后触发，每个群 30 分钟最多一次、每轮最多巡查 3 个群，先使用工具模型，结构化回复无效或调用失败时改用主模型重试，并关闭工具和 Skill。巡查可以回复群聊、只私信主人或保持安静。若要让 bot 读取未提及它的群消息，需要在 Telegram 侧关闭 Bot 的群隐私模式或赋予相应管理权限。

主人私聊和获准群聊可以发送图片、静态贴纸、普通文件、视频、动画、音频和语音。图片及静态贴纸作为图片附件进入会话；其他媒体保存在当前工作区的附件目录，并以受限路径提供给可用工具。Agent 可通过视频阅读 Skill 调用 `biny video analyze` 分析视频。单文件下载上限为 20 MB，每条消息附件合计上限为 40 MB。配置本地语音模型后，Biny 会先在本机尝试转写；未配置本地模型时使用已配置的 OpenAI 服务商。两种转写都不可用时，音频仍保存在附件目录，Agent 会收到该文件的受限路径和未转写提示，不能推断语音内容。联系人、位置和投票会以文本形式交给 Agent。同一媒体组即使分散在连续的轮询响应中，也会收齐后合并成一次会话输入，最多额外等待约 1 秒；白名单群里最近一分钟的图片、文档、视频、动画、音频、语音和贴纸可随下一条提及 Biny 的请求一起处理，每群最多五个文件且所有群合计不超过 40 MB，桥接退出时清空。论坛话题的普通回复会返回原话题。获准群聊中的新表情反应会交由 Agent 判断是否回一个表情，同一群每 30 秒最多处理一次，超过 2 分钟的旧反应会忽略。Biny 当前没有 Telegram 行内按钮；收到按钮回调时会结束加载状态并提示该操作不可用。

设置 `BINY_TELEGRAM_WHISPER_MODEL` 可启用本地语音转写，值为 Transformers.js 支持的语音识别 ONNX 模型 ID 或本地模型目录；首次使用模型 ID 时会下载权重并缓存在全局 Biny 数据目录的 `models/telegram-whisper`。本地解码需要系统可执行的 `ffmpeg`，本地转写限制为 15 分钟；模型加载、解码或转写失败时继续尝试已配置的 OpenAI 服务商。可选的 `BINY_TELEGRAM_WHISPER_LANGUAGE` 用于指定语音语言（例如 `chinese`）；留空时由模型自动识别。模型未配置或转写服务都不可用时，音频仍按附件路径交给 Agent。

启用 Biny Heartbeat 并运行 Telegram 桥接后，Runtime 会把 Heartbeat 通知发送给主人；相同通知按前 200 个字符识别，成功投递两次后才抑制后续重复，Runtime 重启后计数重置。桥接会等 Telegram API 确认发送，再向 Host 确认投递。Bot 必须先收到主人的私聊，Telegram 才允许它向该账号发起消息。Agent 可通过 `biny telegram dm-owner <消息>` 私信主人；只有主人明确要求并提供对方数字用户 ID 时，才通过 `biny telegram dm <用户ID> <消息>` 联系其他用户。回复可发送图片命令生成的图片；自拍相册原图只允许在已验证主人的私聊中按其明确请求发送，群聊只允许发送新生成的图片。群映射及最近消息保存在当前工作区的本地运行数据中。

## 模型切换与辅助请求

Desktop 的模型菜单支持点击和键盘操作：上下键选择入口，右方向键或 Enter 进入模型、推理强度选项；Escape 先返回上一级，再关闭菜单并回到触发按钮。设置页的模型选择器打开后可直接搜索，上下键跳过不可用项，Escape 收起选择器。

聊天输入框会在当前模型明确支持 `priority` 服务档位时显示“快速”开关。新回合会通过当前 Provider 请求优先档位；运行中的请求保持原设置。开关按会话保存，未单独设置的会话沿用 Desktop 最近一次选择。自定义 Provider 或网关需要在模型 Profile 或模型目录中声明 `serviceTiers: ["priority"]`，并实际支持 OpenAI 兼容请求中的 `service_tier` 字段；否则不要启用此选项。

运行中保存新的模型或思考设置，后续根回合采用新选择。当前已开始的回合保持准入时的选择；保存成功不表示当前请求已经换了模型。

同一 Desktop 主窗口中的模型与思考选择按选择顺序保存，切换会话不会重置待完成的顺序。切换项目后，已排队的选择仍使用选择时的项目上下文；共享默认模型与项目覆盖的优先级不变。

输入若仍在等待模型选择保存，离开原聊天后不会再派发这次发送、斜杠命令或继续操作；原草稿保留，返回后可以重新提交。模型选择本身仍按队列完成保存，已经派发的操作不因此取消。

`toolModel` 用于共享辅助模型选择。显式指定时应填写已配置的模型别名；省略时按可用配置自动选择。压缩、记忆处理和活动分析可能额外发起模型请求，其用量与聊天主请求分别记录。 会话内的记忆提取、查询改写、情绪分析、日记和压缩摘要按实际选中的模型别名与请求发起时的价格估算费用；后续切换模型不改写已发起请求的归属，辅助模型缺少价格时保持未知，不借用聊天主模型价格。

文本请求默认使用 `biny` 或 `biny-auxiliary` 作为 User-Agent 的产品名，后接 SDK 标识；显式配置的 User-Agent 保持优先。请求头 `x-biny-operation` 标识主对话或辅助操作，有合法会话 ID 时通过 `x-session-id` 携带。支持这些头的网关可以按稳定会话归集，无会话来源的后台请求不会虚构会话 ID；这些标识不进入模型提示词。

### 辅助请求的凭据续期与取消

复用同一个 Provider 运行实例的文本请求共享进行中的凭据准备。取消其中一个请求不会中断其他仍在等待的请求；没有取消信号的调用也保留等待权。最后一个等待者取消后才取消共享准备，新请求会先等待旧准备结束，避免并发使用旧刷新令牌。

服务商已确认轮换的新凭据仍须保存，取消只阻止该调用后续发送模型请求。旧准备中的真实网络、连接变化或保存失败会传递给等待它结束的新调用，不会被当作取消吞掉后自动重试。普通原生文本调用可以及时返回取消；直接准备和要求等待模型结算的调用仍等待准备与保存结束。内置续期请求保留原有 15 秒网络超时；该超时不保证忽略取消的插件或持久化操作在同一期限结束。

实现见 [ProviderRuntime.ts](../src/llm/ProviderRuntime.ts) 的 `ConfiguredProviderRuntime.prepareTextModel` 与 [nativeJson.ts](../src/llm/nativeJson.ts) 的 `generateNativeText`；合成回归入口为 [provider-credential-cancellation.test.ts](../tests/provider-credential-cancellation.test.ts)。这一共享边界是运行实例，不是所有连接的全局续期锁。

### 聊天输出额度与截断

`chat.maxOutputTokens`（设置中的“最大令牌数”）是每次模型请求的输出上限，不是整轮对话的总额度。默认留空，优先使用当前模型的显式配置，未覆盖时跟随其服务商目录与已知模型元数据；没有声明额度时不发送这一参数，由服务商决定。模型 profile 的输出设置优先于模型别名配置，别名配置优先于自动元数据。自动模式不另设统一的输出额度，切换模型后使用该模型自己的额度。

填写“最大令牌数”会全局覆盖模型额度，切换模型也会沿用；在「设置 → 聊天 → 高级设置」点击“恢复自动”并保存可清除该覆盖，温度等其他聊天设置不变。输出包括正文和工具参数，部分模型的思考也占用这份额度。因此启用高强度思考时，即使可见正文很短，也可能触发长度上限。目录额度只是服务商声明，不保证当前账户可用，也不会让服务商忽略自身限制。

模型返回 `length` 时，Biny 保留已完成步骤与部分回复，将回合标为可继续的未完成状态。提示显示本次请求的有效上限与可用的输出、思考用量，缺失数字不推测。可提高“最大令牌数”，或降低思考强度后继续；提高上限仍受服务商限制，也可能增加耗时与用量。截断的工具调用不会执行，已完成工具不会自动重放。上下文压缩主要减少输入，不能替代输出额度调整。

模型目录中的能力、上下文窗口和价格是元数据。目录刷新失败不证明聊天连接失败，目录存在也不证明账户额度或远端请求可用。

若已知模型的容量因目录来源校验失效而丢失，Biny 会在发送前重新获取当前端点的目录，避免静默改用 32K 保守窗口并频繁压缩。此时目录获取失败会停止本次发送，可在恢复连接后重试；已保存的手动容量覆盖继续优先生效。没有任何已知容量的新型号仍使用带估算标记的保守预算。

目录刷新遇到 HTTP 错误时显示状态、请求地址和最多 8,192 个字符的诊断前缀。尾部读取失败不会抹掉已取得的诊断，错误响应不会替换上次有效目录。

## 图片生成

`imageGen.model` 指定 `biny image generate` / `biny image edit` 使用的默认模型，格式为 `providerAlias:modelId`（例如 `gem:gemini-2.5-flash-image`）或纯 Gemini 模型 ID。留空时按内置优先级从已配置的 Gemini 服务商中自动挑选；显式指定的连接失效、停用或未满足服务商的凭据要求时直接报错，不改用其他模型。自动选择只考虑启用且有凭据的 Gemini 连接。OpenAI 兼容服务商也可指向实现 `/images/generations` 与 `/images/edits` 的本地生图服务；服务商配置 `requiresApiKey: false` 时不发送 Bearer 凭据。`imageGen.localModel` 单独指定 `biny selfie take --nsfw` 使用的模型，必须是 OpenAI 兼容 Provider 且 `baseUrl` 为 `localhost`、`127.0.0.0/8` 或 `::1` 的 HTTP(S) 地址。该命令拒绝远程地址、重定向和远程图片 URL，不会回退到普通生图模型；Agent 代执行时还要求当前 Session 映射到已验证主人的 Telegram 私聊。直接运行本机 CLI 时可使用本地路由。`imageGen.aspectRatio` 指定默认宽高比（如 `16:9`），留空由模型自行决定。

初始化或保存配置时，未显式设置生图选项的 `imageGen` 仍以 `{}` 写入当前格式配置，重新读取时也为空对象。与 CLI 共用配置的 Desktop 需要支持当前配置格式；命令行参数仍可临时覆盖生图设置。

命令行 `--model` 显式覆盖配置。`--aspect`（别名 `--size`）与配置的宽高比同义，显式传入时优先生效；OpenAI 兼容图片 API 会将正方形、横图和竖图分别映射到其标准尺寸。`--reference <路径>` 可重复传入参考图，仅在生成时生效，改图模式忽略；相对路径从当前工作区解析，缺失、空文件或不支持的格式会报错，输入总量限制为 20 MiB。

命令支持 Gemini 的 Generate Content 图片接口、OpenRouter 图片接口与 OpenAI 兼容的 Images 接口；连接能聊天不代表也实现图片 API。`image models` 发现 Gemini 和 OpenRouter 的图片目录，并显示配置的默认项；其他兼容连接需要指定实际图片模型 ID。目录失败会单独报告，配置项本身不证明远端模型可用。

生成结果写入独立的系统临时目录，单张图片最多 20 MiB，命令把文件路径打印到标准输出；模型与路由信息写在标准错误，可用 `--json` 返回结构化结果。图片请求使用 Biny 的代理配置和连接自定义请求头，凭据不放入请求 URL。单次生成默认超时五分钟、目录和结果下载默认三十秒，连接的 `timeoutMs` 可覆盖默认值；失败不会自动重试生成请求。

```sh
biny image models
biny image generate "a cat on a windowsill, afternoon light"
biny image generate --aspect 16:9 "cinematic landscape"
biny image edit /path/to/source.jpg "make the background blue"
```

## 视频理解

Agent 收到视频并被问及其内容时，可通过视频阅读 Skill 调用 `biny video analyze` 使用 Gemini 原生视频理解。命令也可直接读取当前工作区内的视频文件或 `@attachments/...` 附件路径；支持 MP4、MOV、WebM、AVI、MKV、M4V、MPEG、MPG 和 3GP。普通本地文件最大 2 GB，附件路径读取上限为 40 MB。

命令优先使用当前默认模型（默认服务商为 Gemini 时），否则选择已启用且有凭据的 Gemini 服务商；`--model providerAlias:modelId` 可指定模型。请求会将视频上传到 Gemini Files API，分析后立即请求删除远端文件；若删除失败，上传文件由服务端自动过期。

```sh
biny video analyze /path/to/clip.mp4 "Summarize the key events and include timestamps"
biny video analyze '@attachments/clip.mp4' "What did the speakers say?"
```

## 桌面控制

Computer Use 的 `computer.enabled` 默认是 `true`。新配置及缺少该字段的旧配置默认开启，已经明确保存的 `false` 保持关闭。默认开启不会在启动时截图、输入或申请系统权限，首次调用才启动原生组件；系统权限与应用审批仍单独检查。

在「设置 → Computer Use」管理桌面控制开关、系统权限、应用审批、操作日志和画中画。关闭桌面控制开关会停止控制并保存关闭状态，后续使用需要重新开启。「测试我的配置」只检查组件及系统权限，不改变开关；「刷新」同时更新权限、控制状态和应用授权列表。

暂停、重新观察、接管与前台操作选项放在「高级设置」中；组件路径、运行信息、动作限制和错误详情放在「诊断详情」中，两项默认折叠。组件已安装但未运行时显示「按需启动」，不代表组件缺失。

## 本地配置检查

在目标项目目录运行 `biny doctor`，检查全局配置与当前项目 `.biny/settings.json` 合并后的配置。文件读取、JSON、字段类型或模型别名校验失败时，命令显示配置来源和检查方向并以非零状态退出，不回显配置值或解析器的原始 JSON 片段；通过后显示 `configuration: valid`。尚未配置时按运行入口使用默认值，不要求先运行 `init`。项目根目录的旧 `config.json` 仍只提示存在，不会加载。

此检查不会发起模型请求，也不验证 API 密钥、登录状态或远端服务可用性。有效配置中仍有内联 `apiKey` 时会显示迁移提醒，不输出密钥值。

## 排查

| 现象 | 检查 |
| --- | --- |
| 找不到模型别名 | `defaultModel` 与项目覆盖是否引用全局 `models` 中的键。 |
| 缺少密钥或登录过期 | 当前入口的凭据存储、环境变量和服务商登录状态。 |
| 连接存在但请求失败 | 端点协议、实际模型 ID、服务商额度和返回错误。 |
| 修改后当前回合没变化 | 新选择从后续根回合生效。 |
| 全局选择被项目覆盖 | 当前项目 `.biny/settings.json` 的 `defaultModel`。 |

配置结构以 [schema.ts](../src/config/schema.ts) 和 [项目设置](../src/config/projectSettings.ts) 为准；路径解析见 [paths.ts](../src/config/paths.ts)。权限模式另见 [工具与权限](PERMISSIONS.md)。

## 子代理执行预算与权限

子代理默认持续执行到正常交回、取消或故障，不设置固定模型步数和任务总时限。并发、排队容量、单次模型请求与前台命令超时仍各自生效；子代理结束后释放运行资源，执行记录保留供查询。

可在全局配置的 `extensions.subagent` 中显式设置 `maxSteps`（1–100000 轮模型调用）、`timeoutMs`（1000–2147483647 毫秒，包含排队时间）或 `maxCostUsd`。费用阈值要求模型价格信息完整。`inactivityTimeoutMs` 默认 300000 毫秒，每次模型输出或工具进度都会重新计时；只有持续无活动才停止，并显示“无响应”。删除 `maxSteps` 或 `timeoutMs` 字段即取消对应限制；旧配置中已保存的数值继续生效，不会自动当作默认值忽略。费用在请求结束后结算，阈值不能保证最后一次请求绝不超额。

子代理只能使用任务获准的工具集合，并逐次通过父会话的权限管理器判定；只读任务不暴露写入和命令工具。工作区任务可运行所需的有限命令，包括执行刚编写的程序，不再限定为几个测试或构建命令名称。显式拒绝路径传入同一命令沙箱；系统无法落实限制时拒绝启动。子代理仍不提供后台进程、再次委派或任意会话消息能力。

权限拒绝或需要批准时，子代理保存失败调用并停止，向父代理交回精简的操作与原因，不会自动批准或换命令重试。内嵌执行卡片保持只读，分别显示“权限受阻”或“待父代理处理授权”；已结束的任务不会因父代理后续完成工作而改写为成功。父代理可在自己的正常权限流程处理该操作，或在获得必要授权后派发新任务。

## ACP 外部 Agent

Desktop 的「设置 → 服务商」提供 Claude Code（ACP）、Codex（ACP）和自定义 ACP 入口。两个预设已填好启动配置，使用 Agent 默认模型与模式；本机已安装并登录时，点击「连接并保存」即可。首次使用展开「安装与登录」，复制安装、登录命令，在终端依次执行，再回到 Biny 连接。按钮只复制命令，不会自动安装软件或完成账号授权。聊天输入框中选择该连接的模型后，新回合由外部 Agent 执行。连接检查会启动程序并创建一个临时探测会话，不发送聊天任务；外部 Agent 可能自行保留这个会话。连接成功只表示探测会话建立成功，不保证后续模型请求的账号权限和额度。

安装需要 Node.js 和 npm。Claude Code 使用 `npm install -g @agentclientprotocol/claude-agent-acp` 安装，然后执行 `claude-agent-acp --cli auth login` 登录；Codex 使用 `npm install -g @agentclientprotocol/codex-acp` 安装，然后执行 `codex-acp cli login` 登录。两条登录命令使用适配器自带的 CLI。更多平台说明见 [Claude ACP](https://github.com/agentclientprotocol/claude-agent-acp) 和 [Codex ACP](https://github.com/agentclientprotocol/codex-acp)。

启动命令、参数、环境变量、认证方式 ID 和 MCP 名称收在「高级设置」中。自定义 ACP 的启动配置直接展开；已有自定义命令或环境不替换为预设。普通交互式 CLI 不一定支持 ACP。找不到程序时可在高级设置填写可执行文件的绝对路径，并确认 Node.js 在 Biny 的 PATH 中；命令不会经过 Shell，参数须为 JSON 数组，路径中的空格无需额外引号。工作目录始终为当前项目。连接失败不会保存候选配置；连接成功后可选择 Agent 返回的模型和模式，再点击「连接并保存」应用。

以下配置片段可合入全局配置；`default` 表示不覆盖 Agent 的模型选择：

```json
{
  "providers": {
    "external": {
      "type": "acp",
      "acp": {
        "command": "/absolute/path/codex-acp",
        "args": [],
        "env": {},
        "mcpServers": []
      }
    }
  },
  "models": {
    "external-default": { "provider": "external", "model": "default" }
  }
}
```

`acp.env` 保存环境变量引用，例如 `{"API_KEY":"MY_AGENT_KEY"}` 将 Biny 进程环境中的 `MY_AGENT_KEY` 传给子进程的 `API_KEY`。外部进程只继承 PATH、HOME、临时目录、语言及系统运行所需的环境变量，其他变量必须显式映射；HOME 下的原有登录状态仍可使用。从 Dock 启动时，PATH 和临时环境变量可能与终端不同。`authMethodId` 可指定 Agent 的认证方式，`modeId` 可指定它公开的运行模式。`timeoutMs` 控制连接初始化超时，默认 30 秒。`acp.promptTimeoutMs` 控制单轮执行时间，默认 30 分钟；`acp.maxOutputBytes` 限制单轮协议输出，默认 16 MiB，单条协议消息另有 1 MiB 上限。超时或超限会停止连接，不自动重放。

```sh
biny acp check external
biny acp check external --json
biny run --model external-default --json "检查当前项目"
```

ACP 的执行循环、原生工具、上下文压缩和外部记忆由该 Agent 管理。Biny 显示文字、思考与工具事件，保存聊天记录并转交授权回答，不会再次执行这些工具。ACP 连接的「允许此 Agent 接收 Biny 记忆」（`acp.allowMemory`）默认关闭。显式开启且聊天的「使用记忆」也开启时，向量检索命中的共享记忆才作为背景文本随本轮发送。关闭任一开关停止后续注入，不能撤回外部 Agent 已收到或保存的内容。显式传入的任务上下文也会发送。Biny 的 Skills、内置工具和自动记忆写入流程不随 ACP 开启；需要后台辅助模型的功能仍须另配 API 模型。

`acp.mcpServers` 只转交指定名称的已启用 MCP 连接，默认不传任何服务。直接转交相当于授权整个服务，仅在 Biny 完全访问模式下允许。外部 Agent 直接连接这些服务并自行调用工具，Biny 的 Code Mode 编排与逐工具执行控制不参与。当前支持 stdio 和 Agent 声明支持的 HTTP MCP；带隐藏工具策略、文件变更校验契约、独立工作目录、SSE、Keychain 凭据引用或 Biny OAuth 的服务会被拒绝，不能静默丢失这些约束。

每个聊天独立管理外部进程及会话。会话关联保存在聊天 JSONL 旁的 `.acp.json` 文件，重启时仅在 Agent 声明支持 `session/load` 后恢复；不支持时要求新建聊天。启动命令、显式凭据引用的实际值或 MCP 连接变化时要求新建聊天；模型和模式可使用同一外部会话。聊天事件保存 ACP 连接标记；关联文件缺失或切换执行引擎时明确拒绝。旧版未保存标记的 ACP 聊天需新建。外部 Agent 的登录文件或 OAuth 账号变化无法通过标准会话握手验证，切换账号后也应新建聊天。停止先发取消通知，1 秒内未响应则结束进程。异常退出不自动重放任务，未收到结果的工具标记为未知，回合为未完成；待审批请求随回合结束失效，并发审批逐项展示。

ACP 权限请求接入当前 Biny 权限模式，交互批准只选本次授权；这不是操作系统沙箱，外部程序可以自行执行不经 ACP 询问的操作，也能访问当前用户可读的本地文件；关闭记忆不等于限制文件访问。仅连接可信程序，需要强隔离时应在受限系统账号或容器中运行外部 Agent。外部 token 用量与 Biny 内置循环的步数预算暂未接入，执行限制以外部 Agent 为准。当前只支持文本任务；附件、编辑旧消息、重新生成、Biny 断点续跑及跨 Agent 迁移上下文未接入。运行中插话、排队和 Biny 工具选择不可用；切换执行引擎必须新建聊天；会话导出不携带外部 Agent 的私有历史与会话关联。

## 独立视觉模型

通用设置按工具模型、视觉模型、Coding Agent 排列。视觉模型选用已配置且支持图片输入的模型，选择后立即保存为全局 `visionModel`；选择“跟随主模型”清除该项。启用后，图片附件与工具返回的图片由视觉模型生成文字描述，再提交主模型；描述可能遗漏细节，原图仍保留在会话中。识别失败会提示错误，不自动切换模型。每次识别最多 60 秒、输出 4096 tokens，消耗计入用量；同一回合相同图片复用结果，跨回合可能重新识别。

Coding Agent 选择执行后端：自动模式优先使用可执行的本地 Claude Code，未找到时使用内置 Agent；Claude Code 直接使用本机 CLI 及其默认模型；内置 Agent 沿用当前聊天模型。ACP 按已配置的 Provider 连接列出选项，不要求该连接另有 Biny 模型别名，执行时使用 ACP Agent 的默认模型；未配置的目录项不显示，已配置但停用的连接显示为禁用项。卡片显示已配置 ACP Provider 数量，并可跳转到模型供应商设置管理连接。旧选择在用户更改前保留；选择后随设置保存生效。现有权限与外部子代理限制继续适用；外部执行失败不会自动重跑为内置任务。
