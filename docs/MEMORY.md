# 长期记忆

Biny 保存两类不同资料：会话历史记录当时发生的对话与工具操作，长期记忆保存适合以后使用的事实。修改一条记忆不会改写原始会话。

模型主动检索和保存事实使用 `biny memory search "查询" --json`、`biny memory add "事实" --json`，原始对话检索使用 `biny history search "关键词" --json`。搜索可用 `--limit` 设置结果条数（默认 20），用 `--threshold` 覆盖本次相似度阈值（0 至 1，省略时使用记忆设置）。这些命令通过 Shell 执行；自动召回与自动提取独立运行。普通追加允许在当前模型回合中执行，清理与整理仍要求会话空闲。

## 事实如何写入与使用

```mermaid
flowchart LR
    Conversation[已完成对话] --> Extraction[模型提取与更新建议]
    Activity[活动分析候选] --> Auto[自动写入：查重与候选判断]
    Extraction --> Auto
    Manual[明确的记忆管理命令] --> Store[SQLite 事实与归档]
    Auto --> Store
    Store --> Index[派生向量索引]
    Index --> Recall[按当前问题召回有限事实]
    Store --> Search[查看与显式搜索]
    Recall --> Context[本轮聊天上下文]
```

`MemoryStorage` 保存事实身份、正文、标签、重要度、来源锚点和归档关系。`LocalMemory` 编排模型提取、自动写入与 Sleep 整理，向量服务负责检索投影。事实写入和索引更新有各自结果；缺失索引时不能把事实库视为已经丢失。Activity 管线会在尝试其余候选后报告部分写入失败；分析结果保留，但不会自动重放这些写入。

自动贡献先从已完成对话或 Activity 分析中获取候选，再从同一用户范围检索相关事实，判断新增、更新或保持不变。例如已记住“后端偏好 Go，同时使用 pnpm”，用户明确改为偏好 Rust 时，模型可以更新原事实并保留 pnpm 这一未变的信息。更新保留事实 ID，旧正文和来源另存为 `updated` 归档，新旧版本在同一事务中提交；提交前检查旧事实版本，避免覆盖并发编辑。模型判断仍可能出错，归档提供核对和恢复依据。

自动写入要求同一用户范围内已有事实的向量索引完整且模型匹配；空范围可写入第一条事实。必需语义能力不可用、索引缺失或过期、模型响应非法或候选已被修改时，本次自动写入跳过，不把失败当作允许新增；聊天提取没有持久重试队列。提取结果同时含删除与新增时先处理新增，任一新增失败则保留本批待删除事实；本批已确认保留的事实不再删除。用户明确执行的添加与修改直接进入存储校验，不请求自动提取模型。

自动使用记忆发生在回合准备阶段：按当前问题查询可用语义结果，将有限事实加入上下文，而不是加载全部事实。贡献决定是否产生新记忆，使用决定是否自动召回，两个开关分别作用。Sleep 是独立维护过程，整理临时、重复和相似事实，并保留归档与维护记录。

Desktop 输入框的聊天记忆开关同时控制当前聊天的自动使用与贡献。切换只保存聊天偏好，不启动执行进程或加载模型；关闭后，后续消息不自动召回或提取长期记忆，也不做后台主题提取。重新开启不会补提取关闭期间的主题。已有聊天历史与记忆事实不会删除，显式查询和管理操作不受影响。

## 记忆的范围

长期事实使用全局本地记忆库，可跨项目使用。`threadId`、`userId` 和标签用于来源与查询筛选，不构成访问控制或独立租户隔离。

会话历史仍按项目保存。查找“当时具体说了什么”应搜索历史；查找“已经保存的偏好或约定”应搜索记忆。正文、来源时间和关联消息是不同信息，记忆写入时间不代表事实发生时间。

## 查看与搜索

```bash
biny memory list --json
biny memory stats --json
biny memory search "项目约定" --json
biny memory grep "原文片段" --json
```

`list` 默认展示最近更新的 100 条活动事实。`stats` 查看数量和维护状态。`search` 搜索长期事实；`grep` 在对话历史中进行字面匹配，保留查询中的标点语义。

可以按来源筛选：

```bash
biny memory search "部署" --thread-id <session-id> --json
biny memory search "偏好" --tag preference --json
```

语义搜索先按用户、会话和标签限定候选，再取相似度最高的有限结果，范围外事实不会占用名额。指定用户仍可检索未绑定用户的共享事实；筛选不构成身份认证。语义检索需要可用的 embedding，缺失索引或模型不匹配时，自动召回与显式语义搜索均返回空结果及降级原因。没有结果不能据此断言相关事实不存在于全部历史中。

默认使用本地 `Multilingual E5 Small`，也可选择 `All MiniLM L6 v2`。两者使用 Transformers.js / ONNX 生成 384 维向量，权重需要先在记忆设置中下载，安装后可离线检索。模型尚未下载时明确显示不可用，不自动把记忆发送到远端。查询改写和事实提取仍使用配置的辅助模型，因此整条对话链路不一定离线。

Desktop 的“嵌入模型”选择器按本地模型与服务商分组，显示下载体积及可用状态。已有的显式模型选择保持不变；选择远端 Provider 或“自动选择可用服务商”时，查询和待索引事实会发送到对应服务。自动策略显示实际模型及“自动”标记，没有可用服务商时返回不可用。更换模型先确认，再保存设置并重建向量；原始事实保留，旧向量不能用于新模型检索。

## 添加与修正

```bash
biny memory add "项目开发命令使用 pnpm" --json
biny memory get <memory-id> --json
biny memory update <memory-id> --entry '{"content":"项目统一使用 pnpm 10.6.5"}' --json
```

明确的管理命令直接校验并写入事实，不经过自动提取模型。每次 `add` 可以创建独立条目；添加前先查询已有内容，避免把修正写成重复的新事实。`update` 的 `--entry` 必须是 JSON 对象；`null`、数组和其他非对象值会报错，不改变已存事实。

结构化输入可使用 `--entry` 指定标签、重要度等受支持字段。保存稳定且自包含的内容；不要把密钥、猜测或未确认的模型结论当作用户事实。

更新时若提供 `content`，它必须是非空白字符串；非法正文会明确报错，不修改事实或同次提交的其他字段。只调整标签、重要度等信息时可以省略 `content`。

## 归档、恢复与删除

```bash
biny memory archive-entry <memory-id> --yes --json
biny memory archived --json
biny memory restore <archive-id> --json
biny memory delete <memory-id> --yes --json
```

Desktop 搜索记忆时，按 Enter 开始查询；确认输入法候选不触发搜索。搜索完成前重复按 Enter 不重复发起同一查询，修改或清空查询后不展示旧结果。编辑记忆并保存后，保存期间继续输入的草稿会保留，可再次保存。

Desktop 记忆列表和归档列表按页读取，翻页不会重读全库统计。编辑、删除或归档条目后，列表保留当前页；末页被清空时退回仍有条目的最后一页。显式刷新会重新读取列表和统计。

普通归档使事实离开活动召回，仍可恢复；`updated` 归档保存自动更正前的正文，当前版本继续参与召回。恢复使用归档 ID 并创建独立事实，不覆盖仍存在的当前版本；HTTP 与 Desktop 会同时返回当前版本供核对。永久删除活动记忆时，其 `updated` 历史一并删除，其他独立归档不受影响。

直接调用 Runtime Host 的 `archive` 操作时，`archived` 必须明确使用布尔值：`true` 归档，`false` 恢复；缺省、字符串或其他类型会被拒绝，不改变已保存的事实。

`memory archive` 是另一种操作：将会话 transcript 导出为本地 Markdown，不归档长期事实，也不删除会话。`memory clear --yes` 的缺省范围是整个共享事实库；按会话清理需要明确传入 `--thread-id`。执行前确认范围，不能把项目目录当作全局清空的边界。

## 自动处理

启用记忆贡献时，已完成对话可触发后台提取与更新。提取使用模型，可能遗漏或误判；成功的聊天终态也不证明自动记忆处理已经成功。带外部上下文的回合是否参与提取由记忆策略决定。

自动使用记忆与贡献记忆是不同设置。关闭自动处理后，用户明确发起的查询与管理命令仍可使用。Sleep 维护可以整理重复、临时或过期事实，但不会把模型判断变成独立验证证据。

## Sleep 巩固

默认在本地时间 03:00 后、运行时空闲时执行。启动时先识别上次中断的运行，5 秒后首次检查，之后每分钟检查；错过计划时间会在当天补跑。当天已有成功记录则跳过，连续三次失败后当天退避。恢复会启动新周期，不从某条 SQL 的中间继续。

处理顺序是精确去重、临时事实过期、向量聚类及模型合并，随后清理超过保留期的归档。默认 TTL 和归档保留期都是 30 天；明确的 `expiresAt` 到期可归档，否则 TTL 只作用于从未被召回的临时事实。永久事实不会仅因年限而过期。

相似度达到 0.75 时进入候选簇，达到 0.95 的直接重复候选可按保留优先级整理；带临时性或来源时间锚点的事实交给模型判断。默认每批最多 20 条，超过 50 条的簇整簇跳过，并在本轮阶段记录中保留跳过计数。整理按精确用户范围进行，共享事实与绑定用户的事实不互相归档。

模型只能提议保留、删除簇内 ID 或合成事实。合成正文为空、超长或格式错误时整批跳过；新事实及其向量确认可检索后，才在事务中复核来源和替代事实的版本并归档旧条目。任何合成或索引失败都保留来源，记录合成失败数。预览与执行使用同一套保留优先级。运行成功只表示维护流程完成，不能证明模型在语义上没有遗漏事实。

```bash
biny memory sleep
```

## 文件记忆与其他长期上下文

`USER.md` 保存用户资料，`MEMORY.md` 保存可读的长期内容，`memory/YYYY-MM-DD.md` 保存每日笔记。它们与 SQLite 的原子事实分别维护；文件内容不会自动镜像成事实条目。启用相关上下文时读取长期文件及今、昨笔记，缺失文件不因读取而创建。

时间线索负责日期和事件状态，Crystal 组织实体及其材料，活动记录保存桌面行为，会话摘要和项目建议组织跨会话主题。它们保留各自的来源和更新规则，按需提供上下文。日记反思、疲劳状态与 Memory Sleep 也是独立机制。活动采集与日记见[活动记录](ACTIVITY.md)，会话资料见[会话与恢复](SESSIONS.md)。

## 存储与排查

记忆事实、归档和向量投影保存在本地 `agent.sqlite`，该数据库还承载 Activity 数据。向量可重建，事实和活动记录不能当作缓存删除。

遇到旧库结构不兼容，保留原库并按明确迁移流程处理。检索异常先查看 `memory stats`、embedding 配置和服务状态，不通过删除数据库排障。

源码入口：[LocalMemory](../src/agent/context/LocalMemory.ts)、[记忆存储](../src/agent/context/memoryStorage.ts)。自动处理的模型选择见 [模型与配置](CONFIGURATION.md)。
